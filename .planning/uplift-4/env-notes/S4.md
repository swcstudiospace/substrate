# S4 env notes (cache single-flight, stale-while-revalidate, per-class metrics)

Add to `.env.example` / `docs/observability.md` env table at merge. Both are read by `substrate-mcp` only (`config.ts`), from the process environment (`Environment=` / `EnvironmentFile=`); neither takes a list value.

| Name | Default | Meaning | Rollback |
| --- | --- | --- | --- |
| `SUBSTRATE_CACHE_SWR` | `shadow` | `off`: never serve a stale brief. `shadow`: on a brief miss that has a last-good younger than the window, count `substrate.cache.operations{class="brief",result="would_serve_stale"}` and serve the live brief exactly as `off`. `enforce`: serve the last-good, refresh in the background, add `X-Substrate-Brief-Age`. Case-insensitive; anything else (junk, empty, unset) is `shadow`. | `SUBSTRATE_CACHE_SWR=off` (restart). |
| `SUBSTRATE_CACHE_SWR_WINDOW_S` | `30` | How old a last-good brief may be and still be served stale, seconds. Whole number > 0, clamped to a max of 300; 0, junk or empty is 30. | Set `SUBSTRATE_CACHE_SWR=off`. |

Single-flight has no flag (always on, behaviour-preserving). Constants in `cache.ts`: in-flight cap 256, background refreshes 16, a flight older than 15 s is not joined.

Suggested `.env.example` block:

```
# Cache stale-while-revalidate for the brief (uplift-4 S4): off | shadow | enforce. shadow only counts would_serve_stale.
# SUBSTRATE_CACHE_SWR=shadow
# SUBSTRATE_CACHE_SWR_WINDOW_S=30
```

Do not describe the Railway Dragonfly as the production cache in any env text: production is the loopback redis (`DRAGONFLY_URL` points at it); the Railway Dragonfly is idle and an operator decision.
