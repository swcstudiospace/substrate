# S3 environment variables (not added to .env.example)

Every flag below defaults to today's behaviour or to report-only.

| Name | Read by | Default | Meaning | Roll back |
| --- | --- | --- | --- | --- |
| `SUBSTRATE_WATCHDOG` | `packages/mcp-server/src/watchdog.ts` (server process) | `0` (unset) | `1` arms the systemd watchdog: READY=1 once listening, then WATCHDOG=1 every WatchdogSec/3 gated on loop lag and a loopback `/livez`. Only the literal `1` enables it, and only when systemd supplies `NOTIFY_SOCKET`; otherwise a pure no-op (no timer, no child, no request). Set by the example drop-in `20-watchdog.conf.example`, never by the main unit. WARNING: `Type=notify` with this flag off blocks startup. | Remove the drop-in, `daemon-reload`, restart. |
| `SUBSTRATE_WATCHDOG_LAG_MS` | watchdog | `5000` (100-60000) | Event-loop lag at or under which a heartbeat may be sent. | Unset. |
| `SUBSTRATE_WATCHDOG_PROBE_MS` | watchdog | `2000` (100-60000) | Deadline of the loopback `/livez` fetch. | Unset. |
| `SUBSTRATE_WATCHDOG_NOTIFY_MS` | watchdog | `3000` (100-60000) | Hard timeout of one `systemd-notify` child (killed at the deadline, counts as a failure). | Unset. |
| `NOTIFY_SOCKET`, `WATCHDOG_USEC`, `WATCHDOG_PID` | watchdog | set by systemd | Not operator variables. `WATCHDOG_USEC/3` is the ping period; no `WATCHDOG_USEC` (or another `WATCHDOG_PID`) means READY=1 only. | n/a |
| `SUBSTRATE_ALERT_WAIT_S` | `scripts/substrate-alert.ts` (`substrate-alert@.service`) | `60` (0-60; 0 posts at once; a larger value falls back to 60) | Longest wait for the server's loopback `/livez` before the single POST. Capped so wait + POST stays under the unit's `TimeoutStartSec=120` (worst case 83 s: 10 s `systemctl show` fallback + 60 s + 2 s probe + 1 s poll + 10 s POST). | Unset. |
| `SUBSTRATE_RETAIN_RELEASE_MAX_GB` | `scripts/doctor-runtime.ts` (doctor rows) | `6` (0 disables the compare) | Unique release bytes above which the doctor reports `warn` + `would-reclaim`. Report only. | Unset. |
| `SUBSTRATE_STATE_MAX_GB` | doctor | `1` (0 disables) | `/var/lib/substrate` bytes above which the doctor reports `warn` + `would-reclaim`. Report only. | Unset. |
| `SUBSTRATE_JOURNAL_MAX_MB` | doctor | `400` (0 disables) | Journal size above which the doctor reports `warn` + a vacuum hint it does not run. Equals `SystemMaxUse=` in `infra/vps/journald-substrate.conf`. | Unset. |

Per-unit names: the watchdog variables are read only by `substrate-mcp.service` (the example drop-in sets `SUBSTRATE_WATCHDOG` on that unit alone); `SUBSTRATE_ALERT_WAIT_S` only by `substrate-alert@.service`; the three budgets only by the doctor (`substrate-doctor.service` or a manual run). None is a list: each takes one number.

`SUBSTRATE_URL`, `SUBSTRATE_TOKEN`, `SUBSTRATE_TOKEN_SUBSTRATE`, `SUBSTRATE_TOKEN_FILE`, `SUBSTRATE_TOKENS_DIR` are read by the alert exactly as by the doctor (first entry of a token list).
