## What the operator does next

1. **Deploy** as uplift-2 and 3 were deployed: tag on `main`, `SUBSTRATE_HEALTH_TOKEN_FILE=/etc/substrate/tokens/omp infra/vps/deploy-release.sh <tag>` (the gate still refuses below 5 GB free). `deploy-release.sh --dry-run` now prints what the prune would remove, including the case where the previous release goes on the next new-tag deploy. Nothing else is needed for the request path.
2. **Reinstall the unit files** (S3, operator window): `substrate.slice` gains `CPUWeight=300`, `IOWeight=300`, `ManagedOOMPreference=avoid`; `substrate-mcp.service` gains `MemorySwapMax=0` (its RSS is about 53 MB while co-tenant `omp` processes hold most of the 13 GiB of swap). `daemon-reload`, restart, then `bun run doctor:runtime` reads declared against effective. `IOWeight` only bites under an io controller that honours weights; the doctor says when it cannot tell.
3. **Install the doctor timer** (it is dark until you do; uplift-3 N1): the new S3 rows and S7 canary unit are reported by it. Read `bun run doctor:runtime` first.
4. **Switch policies once the shadow numbers look right**, each one env var and a restart:
   - `SUBSTRATE_BRIEF_PROFILE=enforce` after `substrate.brief.profile_bytes_saved{surface=grok-bot}` shows the saving; the gateway should also pass `repo` and send `If-None-Match` (`docs/grok-bot.md`). `SUBSTRATE_SERVED_TOKENS_PER_HOUR` turns the estimated-spend rows from `unconfigured` into a verdict.
   - `SUBSTRATE_CACHE_SWR=enforce` after `would_serve_stale` shows how often a post-write miss would have been absorbed (window `SUBSTRATE_CACHE_SWR_WINDOW_S`, default 30 s).
   - `SUBSTRATE_BRIEF_RECALL=shadow` (needs the cache), read `substrate.brief.recall{result=would_include}` for a few days, then `enforce`. Recall is own-bank only and only for a bearer that is the surface the brief names. `SUBSTRATE_HINDSIGHT_INVENTORY=on` adds the bank gauges and the drift report (names `HINDSIGHT_BANKS` entries missing upstream and `sub-*` banks nobody configured).
   - `SUBSTRATE_METRICS_HISTORY=on` once you have decided the Greptime volume size (recorded as 500 MB in one place and 5 GB in the Notion plan; at 60 s the table adds roughly 29k to 43k rows a day, about 4M at the 200-row batch cap over 14 days).
5. **Make the index recoverable** (S2): mount an off-box path, set `SUBSTRATE_INDEX_ARCHIVE_DIR` and `SUBSTRATE_INDEX_ARCHIVE_MAX_AGE_H=26` on the archive unit's drop-in, install and enable `substrate-index-archive.timer`, then drill it once: `substrate index archive`, `substrate index verify-archive <dir>`, and `SUBSTRATE_INDEX_SCRATCH_URL=<scratch db> substrate index restore <dir>` (it refuses the production database under every loopback spelling). Quarantine and review text, `lease_id` and the write-claim holder are withheld from the files by design.
6. **Optional hang detection** (S3): follow the precondition and install block in `infra/vps/README.md` (a release containing `watchdog.ts` must already be current, then the example drop-in with `SUBSTRATE_WATCHDOG=1`, `Type=notify`, `WatchdogSec=30` and the alert unit). Install `infra/vps/journald-substrate.conf` for the 400 MB journal cap.
7. **Optional docs canary** (S7): ingest `fixtures/docs-golden/corpus`, write the attestation manifest, set `SUBSTRATE_DOCS_CANARY=1` and `SUBSTRATE_DOCS_CANARY_MANIFEST` on its drop-in, enable the timer. A degraded RAGFlow answer exits 3 and posts nothing (an outage is the SLO's to report).

## Rollback

Every item is a flag or an uninstalled unit: `SUBSTRATE_BRIEF_PROFILE=shadow`, `SUBSTRATE_CACHE_SWR=off`, `SUBSTRATE_BRIEF_RECALL=off`, `SUBSTRATE_HINDSIGHT_INVENTORY=off`, `SUBSTRATE_METRICS_HISTORY` unset, `SUBSTRATE_DOCS_TRIGGER_LAG_MIN=0`; the archive, watchdog, alert and canary units are removed by deleting the unit and `daemon-reload`. Reinstall the previous unit files to undo the slice and swap settings. Code rollback is `infra/vps/deploy-release.sh rollback` (previous release kept; unit files are separate). The `metric_samples` table expires on its TTL; `DROP` is an operator action the client refuses.

## Explicitly out of scope (recorded)

Alternates not built, with the reason: a durable spool for collector and CLI emits (Build Plan A-5 "write outbox") is unsafe until the ingest path has a server-side idempotency key, because events carry none and a replay after a timed-out success would duplicate append-only rows; Greptime Flow rollups (flownode availability on the Railway image is unverified); `skills_list`/`skills_approve` audit trail; a redis plus Dragonfly docker conformance suite; `tenant=swc` on every row (needs hash versioning); enforcing `requires/blocks/gated_by` at claim time. Operator decisions this series surfaced and did not make: keep, repurpose or decommission the idle Railway Dragonfly (5 GB volume, 180–310 ms RTT, the loopback redis stays the cache because the `volatile-lru` invariant for the generation and budget counters is not expressible on Dragonfly); the Greptime volume size; installing the redis drop-in and the anchor, index-sweep, doctor and archive timers. Live Hindsight and RAGFlow proofs (Phase 25/26 G1–G4) stay operator-gated.
