# v1.7 requirements audit (41 requirements)

Audited against `main` at a7fbcb3a (PR #194). Each requirement in `.planning/REQUIREMENTS.md` was checked by reading the implementation, grepping the named tests, and reading the docs. Nothing was run: no tests, no live server, no devnet, no LightRAG. Evidence paths are `packages/...` unless stated otherwise. Anything not read is `[INFERENCE]`.

## Grading rule (applied to every row)

Two separate axes. Only the first one grades.

**Repo grade (MET, PARTIAL, NOT MET).**
- MET: the behaviour the requirement states exists in the code, a test in the repository exercises it, and no part the requirement names is missing or defective. Fake servers and stubs count as tests.
- PARTIAL: a named part of the requirement is missing from the code, or the stated behaviour has a defect, or the stated behaviour has no test that reaches it.
- NOT MET: no implementation found.

**Activation (reported per row, never graded).** Whether the feature runs in the default configuration. Flags and their defaults, operator installs (timers, hooks, services), live external proofs (TEI, LightRAG, Dragonfly, devnet, Railway), and CI variables are activation facts. They are recorded here so the owner can see what is live. They do not lower a grade.

Consequence: a feature that is complete in the repo but off by default is MET, and its row says it is off. A feature missing a part is PARTIAL whether or not its flag is on.

## Open findings (defects and drift found by this audit)

Not fixed in this pass. Each needs an owner decision on priority.

- **F1 (ATLAS-04, security, high once the corpus flag is on).** `POST /corpus/ingest` accepts a tombstone for any `{repo, path}` from an authenticated caller, with no scope or tier check (`validate.ts:168-178`, `ingest.ts:476`). The client plan limits this only for the CLI.
- **F2 (REFLECT-02, integrity, medium).** `session_id` is caller-supplied, so one caller can stack feedback votes (`authority-index.test.ts` seeds sessions a, b, c to reach `STALE_FEEDBACK_MIN`).
- **F3 (WATCH-05, low to medium).** `docs.sync` is not in `RESERVED_NOTE_ACTIONS` (`reserved-actions.ts:23-30`), so any authenticated caller can set the lag gauge.
- **F4 (ATLAS-05, medium).** An interrupted run between a plane insert and the superseded-document delete leaves an orphan. Only `corpus reconcile --execute` removes it.
- **F5 (FLEET-01, medium, functional).** The dispatcher ignores `SUBSTRATE_WORKTREE_ROOTS`, and the collector falls back to a hard-coded root.
- **F6 (EVAL-05, low, docs).** `docs/runbooks/docs-rag-operations.md` §5, §6 and §10 disagree with the code (re-rank reader and sync units). The phase 70 record repeats the stale claims.
- **F7 (WATCH-04 and REFLECT-05, medium).** No unit runs a reconcile, so changes no trigger saw are not found automatically. An unchanged digest is never retried after a refused retain.
- **F8 (PROOF-02, low to medium).** The deferred root event is lost on shutdown, so a sync can finish without recording its root.
- **F9 (STEER-05, medium).** A `checkpoint_hint` not consumed before a server restart is lost, so the checkpoint it names is never written.
