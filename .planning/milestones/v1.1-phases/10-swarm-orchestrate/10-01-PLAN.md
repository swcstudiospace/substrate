# 10-01: Swarm event tee, Graph ID minting and binding

## Objective
The swarm's event stream reaches the ledger under one Graph ID per run, attributed to the agent that produced it (ADR 0001 S1, criteria 3-6 and 8, swarm side).

## Tasks
1. `swarm/runlog.py` `emit()`: mint an additive `msg_id` into the JSONL record; tee each record to substrate `POST /events` after the local write.
2. Explicit, exhaustive swarm-type -> `EVENT_KINDS` table (13 types); `swarm_type`, `msg_id`, `correlation_id` in the payload; enum not widened. AST scan of every emit site fails the test on an unmapped type.
   - `plan.updated`, `task.transition`, `task.result.raw` -> `note`
   - `task.claimed` -> `claim`
   - `gate.verdict.unrecorded`, `gate.findings.coerced`, `gate.findings.synthesized`, `gate.findings.unattributed`, `task.result.rejected`, `escalation.request`, `security.dev_key` -> `warning`
   - `script.<name>`, `script.<name>.error` -> `tool.call`
3. Attribution: A01..A15 -> `swarm-aNN-xxx`; `session_id = <AGENT>@<replica>:<graph_id>`; `node_id` = task id.
4. Dedupe on `(surface, msg_id)` in a 24 h window (sqlite under the swarm dir); correlation -> Graph ID cache; `owner/name` repo slug from the origin remote.
5. Graph ID minting `ut-<ts36>-<8hex>`. `scripts/orch_plan.py` resolves `--graph-id` > `SUBSTRATE_GRAPH_ID` > Graph ID in the brief > mint; binds via `graph_bind`, adopting the server's winner; registers the node set with `graph_register`. Nothing time-varying in the hashed brief, so re-plans reuse.
6. Client: stdlib only, stateless JSON-RPC over `POST /mcp`, 1.5 s timeout, outage back-off, fail-open.

## Out of scope (ADR 0001)
No `POST /graph`, no single `agent-swarm` surface, no new event kinds. Deferred: lease bridge (S2), projector (S4), gate verdicts (S5), headless `swarm_run.py` wave summary event.
