# Plan 07-01: surfaces, identity, `graph_bindings` and `graph_bind`, docs

## Objective
agent-substrate server side of ADR 0001 S1 (SPE-5052): a swarm `correlation_id` maps to one Graph ID in the index, and a swarm token can only speak as its own surface.

## Tasks
1. **Surfaces and tokens** — `packages/mcp-server/src/types.ts`: add the 15 surfaces `swarm-a01-orch` ... `swarm-a15-doc` to `SURFACES`. `.env.example`: one `SUBSTRATE_TOKEN_SWARM_*` name per surface (existing `envSuffixToSurface` convention). `config.ts` / `index.ts`: boot warning listing missing swarm tokens on a non-anonymous deployment.
2. **Token names the caller** — `mcp.ts` (`events_emit`, `graph_claim`) and `server.ts` (REST `POST /events`): when the token's surface is `swarm-*` and the claimed surface differs, refuse (REST 403, MCP `isError`); never re-attribute. Non-swarm surfaces and anonymous runs unchanged (collectors rely on it). Tests: `authority.test.ts`, `server.authority.test.ts`, `mcp.test.ts`.
3. **Binding table** — `index-store.ts`: `graph_bindings(correlation_id PRIMARY KEY, graph_id, bound_by, created)` + index on `graph_id`, no FK, inside the existing idempotent `IndexStore.migrate()`.
4. **`graph_bind` MCP tool** — `service.ts` / `mcp.ts`: create (insert-or-read, one winner), forward (correlation -> graph), reverse (graph -> correlation ids). On create only, one fail-open `note` event under its own session `bind:<graph>:<corr>`. `observe.ts` coverage. Tests: `graph-bind.test.ts`.
5. **Audit policy** — `packages/audit/src/policy.ts` (+ test): `graph_bind` explicitly classified fail-closed.
6. **Docs** — new `docs/swarm-correlation.md`; `docs/mcp-audit.md`; README paragraph.

## Out of scope (deliberate)
- Versioned migration runner: not needed; would be a second DDL convention.
- `POST /graph` REST door, a single agent-swarm surface, new event kinds: ruled out by ADR 0001. `EVENT_KINDS` stays at 12.

## Verification
- `tsc` clean; full suite with and without live Postgres; `store-lock.test.ts` passes.
- Live end-to-end smoke against `postgres:16` + `greptime/greptimedb:v0.14.4` (with phase 10).
