# Plan 08-01: Swarm memory through the governance gate

**Objective:** swarm memory is substrate memory; every gate refusal is handled, not worked around. ADR 0001 S3 (SPE-5054).

## Tasks

### Task 1 (agent-substrate): pin swarm-surface grants from the outside
- Confirm the 15 swarm surfaces are covered by the existing wildcard default grants in `memory-policy.ts`; change a grant only if a test shows a gap (none expected).
- Tests asserting, through the gate, what a swarm surface may write: `decision` + `fact` at `graph:` and `repo:`; `fact` only at its own `agent:` scope; refused at another agent's scope and at person scope; unknown writer refused; `global` returns `review.required` (proposal, not stored) until a reviewer token releases it.
- `docs/memory-governance.md`: swarm section.

### Task 2 (agent-swarm): `swarm/memory.py` client
- Kind map `decision/retro/pattern -> decision/fact/fact`; scope map `graph/repo/agent/global`.
- `idempotency_key = sha256(correlation|task|attempt|kind|scope|text)`, reused across retries.
- Outcomes: `denied -> E-POLICY`; `quarantined` and `review.required` returned, not retried; `version.*` conflict -> re-read, resubmit with `expected_version`; `verified_persisted: false` -> retry with the same key; ok only when `accepted && verified_persisted`; unreachable -> `unavailable`.
- `memory_query` via `memory_search`; `run_start_context` via `/brief`; `substrate_client.mcp_call_json`.
- `swarm_run.py`: assignment prompt gains a "Substrate memory" section only when the substrate answers.
- AST scan test: no swarm-side store feeds an agent's context. `docs/substrate-memory.md`.
