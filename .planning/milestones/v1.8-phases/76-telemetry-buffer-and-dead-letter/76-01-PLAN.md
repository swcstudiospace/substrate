# Phase 76 Plan 01: Telemetry buffer and dead-letter

Branch `gsd/v18-p76-telemetry-dlq`, worktree `/root/src/worktrees/as-gsd-v18-p76`, stacked on phase 73 (`recordIngest`, the hash chain and `event_ingest` are its write path and are kept as they are).

Goal: an event whose Greptime write fails is buffered, retried with backoff, and after its budget written to a dead-letter record carrying its hash. No event is dropped silently.

## Discovery (confirmed)

- `GreptimeClient.insertEvent` (`greptime.ts`) has no retry: one `INSERT`, then `recordIngest`. A thrown error propagates unchanged.
- `Substrate.appendChained` (`service.ts`) catches that error and returns `{ event, stored: false, error }` with nothing queued. The chaos scenario in `packages/audit` relies on this fail-open shape.
- `/healthz` is `server.ts`: it spreads `substrate.health()` (`service.ts`, typed `SubstrateHealth`) into the body, plus `idempotency`, `auditDurable`, `hindsight`, `recall`. A new field on `SubstrateHealth` appears in the body with no server change.
- The retain outbox (`retain-outbox.ts`, uplift-2 R3) is the precedent: a bounded queue, backoff with jitter, an attempt ceiling, drop causes, a 0600 JSONL file with compaction, and a memory mode reported as `durable: false`. This phase follows its shape.

## Decisions

- **D76-01 Dead-letter store is a local JSONL file, not a Greptime table.** The dead-letter path is exercised when Greptime is failing, so it cannot depend on Greptime. A file is one append per record, needs no DDL and no append-mode check, and survives restart. `SUBSTRATE_EVENT_DEAD_LETTER_PATH` unset keeps records in memory and reports `durable: false`, as the retain outbox does.
- **D76-02 The buffer is per-session FIFO, bounded.** `SUBSTRATE_EVENT_BUFFER_MAX` (default 256, positive) bounds the entries. `SUBSTRATE_EVENT_BUFFER_PATH` (unset = memory) persists them. Sessionless events have no chain, so each is its own entry with no ordering promise.
- **D76-03 A later event waits behind its session's buffered events.** While a session has buffered entries, a new event for that session is queued, not written directly, and its `prev` is the hash of the buffered tail. Otherwise `prev` is the ledger tip, read by `lastHash` at turn start as today. The hash covers `prev`, so `normalizeEvent` is unchanged and the chain stays intact.
- **D76-04 Writes stay inside the session turn.** `emitChains` already serialises appends per session. Drain deliveries take the same turn, so a drain cannot interleave with an emit that reads the tip. The turn helper is extracted from `append()` and used by both.
- **D76-05 The event id is the idempotency key for retries.** `GreptimeClient.insertEvent(event, { mayExist: true })` first checks whether an `agent_events` row with that id exists in its cell (`surface, repo, graph_id, kind, ts`, the same bounded predicate as `findByIdempotencyKey`). A present row is not inserted again; its `event_ingest` record is repaired when missing. The default path (`mayExist` unset) is unchanged and adds no read.
- **D76-06 A dead-lettered event takes its session's later buffered events with it** (reason `predecessor-dead-lettered`). Their `prev` link names the dead event, which can never land, so writing them would break the chain for the session.
- **D76-07 Overflow dead-letters the oldest buffered event that is not in flight** (reason `overflow`, with the same cascade as D76-06). If nothing can be evicted, the incoming event is dead-lettered (reason `buffer-full`) and the caller is told.
- **D76-08 Backoff and budget.** Base `SUBSTRATE_EVENT_BUFFER_BACKOFF_MS` (default 1000), doubling, capped at `SUBSTRATE_EVENT_BUFFER_BACKOFF_CAP_MS` (default 60000), ±20 % jitter. `SUBSTRATE_EVENT_BUFFER_MAX_ATTEMPTS` (default 10) counts the live write. The attempt that reaches the ceiling dead-letters the entry (reason `exhausted`). A drain pass stops at the first transient failure, since the ledger is probably down.
- **D76-09 Response contract.** A buffered event answers `stored: false, buffered: true, error: <cause>`. It is never `stored: true` until it lands. A dead-lettered event answers `stored: false, deadLettered: true`. A keyed replay of an event still queued (same surface and `_ik`) answers the queued event with `buffered: true` and writes nothing, so the CLI spool's replay on 503 cannot duplicate it.
- **D76-10 Unchanged refusals.** A chain-tip read failure and an append-mode refusal stay `stored: false` with no buffering. They are not write failures, and buffering would hide a configuration problem.
- **D76-11 Shutdown.** A durable buffer keeps its entries for the next boot. A memory buffer is dead-lettered with reason `abandoned`, so the process exit leaves a record for each entry.
- **D76-12 `/healthz` reports, it does not gate.** `SubstrateHealth.eventBuffer` carries `depth`, `max`, `oldestAt`, `durable` and `deadLetter: { depth, durable }`. Depth does not change the status code, which is still set by writability, as before.
- **D76-13 The dead-letter store is not bounded.** Bounding it would have to drop records, which is the silent loss this phase removes. Its depth is reported, and the buffer bound is the flag-controlled limit. This is the one reading of criterion 2 that does not contradict the goal.
- **D76-14 Deferred.** A buffered `session.end` does not close its steering session, and a buffered event does not run `noteDocsCanary`, until it lands. A landed event publishes its wake-up hint. Recorded as an open risk in the SUMMARY.

## Criteria

1. Failed write enters the bounded buffer, is retried with backoff, and after the budget is dead-lettered with its hash: D76-02, D76-05, D76-08, the `exhausted` path. Tests above.
2. Depths in `/healthz`, bounded by a flag: D76-12 and D76-13 (buffer bounded; dead-letter depth reported, unbounded by design). Tests above.

Verification is run once by the orchestrator after this worker lands.

## Follow-up: the buffer is opt-in and file-backed (supersedes D76-02 and D76-08's default path)

- **D76-15 Off by default.** The buffer runs only when `SUBSTRATE_EVENT_BUFFER_PATH` is set. Unset, `Substrate` builds no buffer and no dead-letter store, and a failed write answers `stored: false` exactly as before the phase.
- **D76-16 Dead-letter path required.** While the buffer is on, `SUBSTRATE_EVENT_DEAD_LETTER_PATH` is required. `loadConfig` throws `ConfigError` naming `SUBSTRATE_EVENT_DEAD_LETTER_PATH` when it is missing, so boot refuses. There is no memory-only mode in configuration.
- **D76-17 Injection, not configuration, for memory.** The classes still accept a null path, so unit tests of `EventBuffer` and `DeadLetterStore` run in memory. No service test needs an in-memory store: the service tests use temp files, and abandon their substrates after each test.
- **D76-18 Health shape.** `/healthz.eventBuffer` is `{ enabled: false }` when off, and `{ enabled: true, depth, max, oldestAt, durable, deadLetter }` when on.
- **D76-19 Residuals, documented, not closed.** A buffered `session.end` does not close its steering session until it lands. Sessionless buffered events have no chain, so they are independent entries with no ordering promise.
- **Tests.** Boundary tests in `service-event-buffer.test.ts`: buffer set without a dead-letter path refuses boot and names the variable (`a buffer with no dead-letter path refuses boot...`); buffer unset keeps the `stored: false` reply and buffers nothing (`with the buffer unset, a failed write answers stored false...`); a restart re-reads the buffer (`a restart re-reads the buffer...`). The existing suites `ledger-chain.test.ts` and `event-idempotency.test.ts` are reverted to their original text.
