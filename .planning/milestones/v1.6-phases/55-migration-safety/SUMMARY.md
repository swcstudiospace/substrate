# 55-SUMMARY: Migration safety, session event vocabulary and the v1.6 baseline

## What was built

- **Contract tests for index migrations** (`packages/mcp-server/src/index-store.migrate-contract.test.ts`). Rules: (a) idempotent statements, (b) no destructive statement, (c) the applied text of every step matches a frozen sha256 digest (`index-store.migrations.digests.json`, steps 1 to 32, generated by `scripts/migration-digests.ts`), (d) every created table is archived (`ARCHIVE_TABLES`) or allowlisted with a reason, (e) the reversible-step convention. Each rule has a fail-before test that feeds a violating synthetic step list.
- **Fake-connection harness** (`index-store.migrate-harness.test.ts`) through a new `IndexStoreOptions.sql` seam; the production default is unchanged. It proves the advisory lock is taken before any DDL, one transaction per step with the ledger insert inside it, rollback with no ledger row, zero DDL on a re-run, and resume from a partial ledger.
- **`MigrationStep` gained optional `down` and `phase` fields**, required from step 33 and enforced through synthetic lists, because no step on main is at or above the first reversible version. `migrate()` never runs a `down`; it is documentation for an operator.
- **Rollback-compat pin** (`rollback-compat.test.ts`): every index step added since the reference release 9231f43 must be additive and named in `docs/runbooks/rollback-compat.md`.
- **Session event vocabulary** (`session-events.ts`, `session-events.test.ts`): `session.checkpoint` and `session.rollback` as `note`, `session.rollback.refused` as `warning`, strict payload validators and builders, a 16000-byte cap check, idempotency keys, and three `EVENT_SOURCES` rows in `event-sources.ts` with the rows in `docs/event-vocabulary.md`. EVENT_KINDS stays 12 and SURFACES 42.
- **Operator rehearsal runbook** `docs/runbooks/index-migration-rehearsal.md`; every production step in it is operator-run (HARD_STOP).
- **The milestone discovery record** `CONTEXT.md` (commit f71cc1b), which also holds the ten corrections to the plan's assumptions.

## Key decisions

- No new index migration step, table or column was added by this milestone on `gsd/v16-int`; step 33 is reserved by an unmerged draft.
- A migration's `down` is documentation only. Rollback is code only (`docs/runbooks/rollback-compat.md`).
- A new ledger concept is a `payload.action` on an existing kind, never a new kind or surface.

## Deviations from the plan

- The plan assumed a migration tool was missing per store. The repository already had an in-repo engine (`MIGRATION_STEPS`, ledger table `schema_migrations`, session advisory lock, one transaction per step), so the phase added tests and a seam instead of a tool (CONTEXT correction 5).
- GreptimeDB and Dragonfly got no migration work: Greptime has no ALTER path except one TTL statement, and Dragonfly keys are already versioned (`substrate:v1:`).

## Findings

- **Fixed:** the index row of `docs/runbooks/rollback-compat.md` was wrong. Commit 9231f43 predates the migration ledger and steps 17, 18, 31 and 32. The row is corrected and pinned by `rollback-compat.test.ts`.
- **Recorded, not fixed here:** production has no migration ledger before the first `migrate()`, so the first run replays every idempotent step; the playbook is in the rehearsal runbook and is operator-run.
- The stale prose in `docs/event-vocabulary.md` that said the session events were not wired to any tool was corrected in the v1.6 close documents.

## What remains

- The production rehearsal and any production migration: operator-run, never done.
- A hypertable or Timescale policy needs its own rehearsal on the Timescale image and an operator decision; none was created.
