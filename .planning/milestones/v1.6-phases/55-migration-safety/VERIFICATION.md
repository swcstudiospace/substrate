## Residual risks

- The rehearsal itself was never run against a production-shaped database; the runbook is untested against the live Timescale image (it says the index uses no Timescale features). Operator-run.
- Production has no migration ledger before the first `migrate()`; the first run replays every idempotent step. The playbook exists; the run does not.
- The digest fixture grew from 32 to 34 steps when phase 58 (PR #137) added steps 33 and 34. The contract test checks the real `MIGRATION_STEPS` against the fixture, so any future step that lands without a regenerated fixture fails loudly; the risk is only that two branches adding steps concurrently must regenerate in merge order.
- Resolved since the prior record: step 33 is no longer reserved by an unmerged draft and the merge-order question is settled — steps 33 (`planning_steering_audit`) and 34 (`planning_steering_audit_reason`) are on main via phase 58 (PR #137), the `down`/`phase` convention is enforced against real steps (`"every real step at or above the first reversible version (33, 34) declares down and phase"` in the contract test, `FIRST_REVERSIBLE_VERSION = 33` in `index-store.ts`), and `migrate()` skips both unless the steering-audit opt-in is set.
