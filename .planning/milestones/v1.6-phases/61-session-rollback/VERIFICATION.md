## Residual risks

- **Criterion 3:** no hook calls the CLI at turn, plan-step or steering boundaries. The entry points (`substrate session hook`), the policy and the printed Claude Code / git post-commit configuration are shipped (PR #148); firing them from omp, GSD-Core, Ultrathink, Swarm, a steering-delivery host, or an operator-installed host hook is outside this repository (ADR 0007, decision D55-4). Swarm's tool allowlist still does not include the new tools and a Swarm lane's guard blocks `git checkout` and `git restore`; no sibling repository was changed.
- Rollback was never rehearsed against the live server or the live ledger.
- Resuming an omp forked session file is UNVERIFIED for the installed omp; who takes omp checkpoints automatically is unverified (`--omp-session` exists, but no shipped hook calling it was verified; runbook). The omp bucket name for a working directory outside the home and temp roots was not checked against a real directory.
- A `verified` memory status in a checkpoint view proves a hash and an anchored cited event, not that the event concerns the entry.
- `refs/substrate/*` can hold untracked files and ignored `.planning/` notes; they must never be pushed (`docs/runbooks/session-rollback.md`, "The checkpoint refs: do not publish them").
- A rollback is crash-recoverable and verified, not atomic across files: a crash leaves the worktree partly restored until `substrate session recover`.
- No REST twin of the three tools exists, so a client without MCP cannot use them.
- Resolved since the previous record: the multi-process checkpoint `seq` race now has a lock (PR #146, commit 71d308f5; `checkpoint.ts` allocates `seq` and pins under `<git dir>/substrate-checkpoint.lock`; `checkpoint.test.ts` `describe("sequence allocation across callers sharing one git directory")`: `"two checkpoints started together get two distinct, contiguous seqs"`, `"two processes making checkpoints at once never pin the same seq"`, stale-lock breaking). PR #148 also closed the hook-at-deadline journal gap (pending record written before the request, removed on acceptance) and the double-hash of the first automatic checkpoint.
