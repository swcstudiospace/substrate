## Residual risks

- **Unverified against a live system:** the Hindsight document-listing route the verifier reads (`GET <plane>/v1/default/banks/<bank>/documents?limit=&offset=`) is unverified against Hindsight 0.9.1; when the plane lacks it the orphan and duplicate checks are skipped and reported. What a live LightRAG returns to the tandem leg is also unverified (none is deployed).
- **Ledger pairing is exact only for events written after the entry-id upgrade (PR #143).** Legacy `memory.write` events written before the key existed carry no entry id and are still paired by the writer+scope+kind+time heuristic, exact in count within a bucket and approximate in identity; when an exact event and a legacy event contend for the same two entries the verifier reports `ledger_pairing_ambiguous` and never guesses.
- A memory-only retain outbox (no `SUBSTRATE_RETAIN_OUTBOX_PATH`) cannot be read by the runner, so a missing plane document may be a retain still waiting.
- A checkpoint's `verified` memory status proves the entry hash and an anchored cited event, not that the event concerns the entry (phase 60).
- Criterion 3 names expiry; no expiry or operator caller of the forget primitive exists (only the rollback commit calls it).
- The forget plane delete depends on Hindsight's document delete route being the one the existing `deleteDocument` uses; no live call was made.
