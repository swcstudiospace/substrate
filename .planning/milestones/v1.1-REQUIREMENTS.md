# Requirements: Agent Substrate

**Defined:** 2026-10-07
**Core Value:** Every agent on the host shares one brief, one event log, one governed memory plane and one Graph ID.

Source of truth for this milestone: ADR 0001 `docs/adr/0001-agent-swarm-as-sdlc-mesh-on-substrate.md` on `origin/main` (accepted design) and Linear SPE-5052 (S1) and SPE-5054 (S3). An earlier draft of these requirements invented a `POST /graph` door, a single `agent-swarm` surface and new event kinds; the ADR rules all three out and this file replaces that draft.

## v1.1 Requirements

### Database structures (Phase 7, repo `agent-substrate`, SPE-5052)

- [x] **DB-01**: A swarm `correlation_id` binds to exactly one Graph ID in a durable index row (`graph_bindings`, unique on `correlation_id`); a retry holding only the `correlation_id` gets the Graph ID back and two racing binds resolve to one winner and one reader.
- [x] **DB-02**: The binding can be looked up both ways (`correlation_id` to Graph ID, Graph ID to `correlation_id`s) through the MCP tool `graph_bind`.
- [x] **ID-01**: `SURFACES` carries the 15 swarm surfaces `swarm-a01-orch` to `swarm-a15-doc`; `.env.example` lists a `SUBSTRATE_TOKEN_SWARM_*` entry for each and boot reports any that is missing on a non-anonymous deployment.
- [x] **ID-02**: A token for one swarm surface cannot emit an event or claim a node as another swarm surface (refused, never re-attributed) on MCP `events_emit`, MCP `graph_claim` and REST `POST /events`. Other surfaces keep today's behavior.
- [x] **ID-03**: `EVENT_KINDS` stays the closed 12-kind set and no file outside `packages/mcp-server/src` touches the ledger (`store-lock.test.ts` still passes).

### Orchestrate integration (Phase 10, repo `agent-swarm`, SPE-5052)

- [x] **TEE-01**: Every event the swarm publishes through `runlog.emit` is teed to substrate `POST /events` with `surface` = the emitting agent, `session_id` = `<AGENT>@<replica>:<graph_id>`, `graph_id`, `node_id` = task id, `kind` from an explicit swarm-type table, and `swarm_type`, `msg_id`, `correlation_id` in the payload.
- [x] **TEE-02**: The swarm-type to `EVENT_KINDS` table is exhaustive over every type the repo emits; an unmapped type fails a test.
- [x] **TEE-03**: The tee dedupes on `(surface, msg_id)` inside a 24 h window; a double-publish produces one request.
- [x] **TEE-04**: The tee fails open: with the substrate unreachable, `orch_plan` and the swarm flows complete exactly as before.
- [x] **GID-01**: Swarm work with no upstream ultrathink prompt mints a Graph ID `ut-<ts36>-<8hex>`, binds it to the correlation id, adopts the server's winner on conflict, and registers the node set with `graph_register`.

### claude-ultrathink integration (Phase 9, repo `claude-ultrathink`)

- [x] **UT-01**: After a prompt is planned and its session record is written, ultrathink emits one fail-open `note` event carrying the Graph ID, with no prompt text.
- [x] **UT-02**: With no substrate URL, `SUBSTRATE_DISABLED=1`, a timeout or a rejecting emitter, the hook result is identical to a run without the substrate.

### Memory structures (Phase 8, repos `agent-substrate` and `agent-swarm`, SPE-5054)

- [x] **MEM-01**: The swarm memory kind map (`decision` to `decision`, `retro` and `pattern` to `fact`) and scope map (`graph:<id>`, `repo:<owner/name>`, `agent:<swarm surface>`, `global`) are implemented and tested.
- [x] **MEM-02**: Each gate outcome has a tested swarm handler: `denied` fail-closed, `quarantined` recorded and not retried, `conflict` with `version.required|stale` re-read and re-submitted with `expected_version`, `conflict` with `review.required` carried as a proposal.
- [x] **MEM-03**: Nothing acts on a write unless `accepted` and `verified_persisted`; every swarm write carries an `idempotency_key` derived from `(correlation_id, task_id, attempt, content)`.
- [x] **MEM-04**: Default-deny is proven from outside: a swarm surface writing at a scope it has no grant for is refused. The 15 swarm surfaces get explicit default grants in `memory-policy.ts`. (Corrected during phase 8: no grant was added because the wildcard default grants already cover the swarm surfaces; default-deny is proven from the outside by tests.)
- [x] **MEM-05**: No swarm-side store is read on any agent context path, proven by a test in the swarm repo's own suite.

### Proof (cross-repo)

- [x] **PROOF-01**: Against a real Postgres and a real GreptimeDB, an `orch_plan` run binds a Graph ID, its events appear under that Graph ID in `events_query`, `events_verify` is green, and a token for `swarm-a05-be` is refused when it emits as `swarm-a09-rev`.

## Deferred (needs your decision, not built in v1.1)

- **Self-improving memory bank** (lessons with citation IDs, success score, digest roll-up, phase lifecycle events). Source: the research on PR #10 (SPE-5830). It asks for sign-off per tier and must fit the governance model that is already on `main`: memory kinds are a closed set, `memory_write` is the single write door, and `store-lock.test.ts` fails the build on a second memory write path. A separate lessons table with its own insert path would break that. Decision needed: store lessons as governed `fact` entries (recommended) or change the rule.
- ADR phases S2 (lease bridge, SPE-5053), S4 (projector, SPE-5055) and S5 (gate verdict events, SPE-5056).

## Out of Scope

| Feature | Reason |
|---------|--------|
| Widening `EVENT_KINDS` or adding a `/graph` REST door | ADR 0001: enum is closed, REST doors are fixed, graph tools stay MCP-only |
| One shared `swarm` or `agent-swarm` surface | ADR 0001: would collapse 15 memory writers and 15 lease holders into one |
| A second Greptime client or MCP server | Non-goal 1 of ADR 0001 |
| Replacing the NATS bus | Non-goal 3 of ADR 0001 |
| Resolving PR #10 / PR #4 merge conflicts | Real conflicts needing judgment; reported, not resolved |
