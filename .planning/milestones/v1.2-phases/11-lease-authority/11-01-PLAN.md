# Plan 11-01: swarm session shape, holder-only `lease_id`, `not-holder`, no swarm operator

## Objective
agent-substrate server side of ADR 0001 S2 (SPE-5053): the substrate refuses any lease action a swarm agent is not entitled to. A swarm session names its agent, replica and graph; a `lease_id` reaches only its holder; only the holder's token surface can beat, release or complete; a swarm token is never an operator.

## Tasks
1. **Holder check and redacting views (pure)** — `packages/mcp-server/src/lease.ts`.
   - `decideHeartbeat` / `decideRelease` take `caller: Surface | null` in the request; new refusal `not-holder` when `caller` is non-null and is not the holder's surface, checked before the `lease_id` compare. A null caller is not checked; `force` skips the check.
   - `decideClaim`'s `denied` carries `lease_id: null`.
   - `leaseView` is the public view (`lease_id: null`); new `holderLeaseView` keeps the id.
   - Verify: `lease.test.ts` — denied claim has no id; another surface is `not-holder` on heartbeat and release with the right id; same refusal with a wrong id; the holder's surface works; anonymous unchecked; force unaffected; free node `unheld` / `noop` for anyone; `leaseView` has `lease_id: null`, `holderLeaseView` the id.
2. **Index store** — `packages/mcp-server/src/index-store.ts`.
   - `heartbeatNode(graph, node, leaseId, caller, ttl)` and `releaseNode(graph, node, request, caller, alsoSetState?)` thread `caller` into the decisions. The SQL fences are unchanged (a holder change always mints a new id, so the `lease_id` fence pins the holder).
   - `claimNode` returns `holderLeaseView` on a grant and `leaseView` on a denial; `heartbeatNode` returns `holderLeaseView` only when accepted.
   - `reapExpiredLeases` returns `lease_epoch` instead of `lease_id`.
   - Verify: `index-store.lease.test.ts` (live PG, `SUBSTRATE_TEST_PG_URL`) — loser and refused views carry `lease_id: null`; a different surface is refused `not-holder` on heartbeat, release and complete even with the id, and the node stays held and not completed; an operator's force is not held to the holder; the reaper reports the epoch and no `lease_id`; stale-id tests move to same-surface/different-session holders so `lost` / `stale-lease` stay covered.
3. **Service** — `packages/mcp-server/src/service.ts`.
   - `heartbeatNode(…, caller, ttl?)`, `releaseNode(…, request, caller, alsoSetState?)`, `completeNode(…, request, caller)`.
   - The claim withdrawal passes the claimant's surface; the handoff release passes `from.surface`, or null when `config.allowAnonymous`.
   - `getGraph` / `registerGraph` null every node's `lease_id`; `claimNode` nulls `node.lease_id` always and `lease.lease_id` unless the claim stands.
   - Claim, note, warning and reaper payloads carry `lease_epoch`, not `lease_id`.
   - Verify: `service.test.ts` — steal payload has `lease_epoch` and no `lease_id`; refused claim hides the id; another surface's release/complete is `not-holder`, writes nothing and shows no id; release note payload `{action, lease_epoch}`; withdrawal is made as the claimant; handoff release held to the authenticated sender, unchecked when anonymous; packet carries `lease_handover` and never the id.
4. **Handoff packet** — `packages/mcp-server/src/handoff.ts`.
   - `HandoffPacket.lease_handover: boolean` replaces `handover_lease_id`; the input field stays request-only.
   - `handover_lease_id?` is kept on the packet type as a legacy read shape. `HANDOFF_VERSION` is unchanged.
   - Verify: `handoff.test.ts` — `lease_handover` is signed (tampering breaks it); a packet signed with the old `handover_lease_id` field still verifies after a JSON round trip, and tampering with that field breaks it; the built packet never holds the id.
5. **MCP surface** — `packages/mcp-server/src/mcp.ts`.
   - `swarmSessionRefusal(surface, sessionId, graphId)` and `SWARM_REPLICA_PATTERN` (`^[A-Za-z0-9._-]{1,64}$`). The agent is derived from the surface, and the graph is compared by equality. Applied in `graph_claim` when the attributed surface is a swarm surface; refused with `isError`, and the index is never asked.
   - Pass `callerSurface` to heartbeat, release and complete.
   - Update the descriptions of `graph_claim`, `graph_heartbeat`, `graph_release`, `graph_complete` and `coord_handoff`.
   - Verify: `authority.test.ts` (pure session cases); `mcp.test.ts` — bad sessions refused before the index; the rule follows a swarm holder named by an anonymous caller; `graph_get` / `graph_register` show the holder and `lease_id: null`.
6. **No swarm operator** — `packages/mcp-server/src/config.ts`.
   - `isOperator` is false for a token whose surface is a swarm surface.
   - `configWarnings` names the listed swarm surface(s) without printing the token. It is wired at boot by the existing `index.ts` loop.
   - Verify: `authority.test.ts` — refused even when listed; the warning names `swarm-a05-be`, not an unlisted surface and not the token. `server.authority.test.ts` — over HTTP `/mcp`, A09's token (listed as an operator) is refused `force`; another surface is refused `not-holder` with the holder's id and sees no id; the holder's token beats; bad A05 sessions are refused.
7. **Drift** — `drift.ts` is unchanged; the public `leaseView` redacts it. Verify: `drift.test.ts` — no claim or finding (orphaned, expired) carries the id; holder, epoch and expiry show.
8. **Docs** — `docs/coordination.md`: contract, "Only the holder sees, or uses, a lease", the no-swarm-operator rule, event payloads and the handoff packet. `docs/swarm-correlation.md`: new "Swarm leases" section covering session shape, holder-only ids, `not-holder` and no swarm operators. `README.md`: one line each in Coordination and the swarm paragraph.

## Changed contracts (deliberate)
- Replies: `lease_id` is null except on a grant and an accepted heartbeat. `coord_reap_leases` rows carry `lease_epoch` instead of `lease_id`. Lease event payloads carry `lease_epoch` instead of `lease_id`. Handoff packets carry `lease_handover` instead of `handover_lease_id`.
- Fenced calls: a token whose surface is not the holder's gets `not-holder`. A non-swarm token that claimed as another surface is therefore locked out of its own claim (documented).
- `force` from a swarm token is always `force-requires-operator`.

## Out of scope (deliberate)
- Session-level holder check, REST lease routes, operator-gating `coord_reap_leases`, scrubbing historic events/packets.
- `EVENT_KINDS` stays at 12; no new tool.
