# S6 env notes (orchestrator applies)

## `.env.example` block

Place directly after `SUBSTRATE_METRICS_HISTORY_TTL=` (the uplift-4 S6 block).

```sh
# Which series the metrics history samples and serves (uplift-5 S6): `core` (default)
# is the 11 series above; `extended` adds the promotion evidence (cache results,
# brief profile bytes saved, brief recall and recall prefetch results, expired
# memory reads, retain outbox and index archive gauges), roughly 10-17 more rows per
# sampling interval in normal use. Opt-in because the Greptime volume size is
# unresolved (500 MB in one record, 5 GB in another). Anything else is `core` and
# is named at boot. See docs/dashboards.md.
SUBSTRATE_METRICS_HISTORY_SERIES=
```

## Variables

| Name | Default | Meaning | Rollback |
| --- | --- | --- | --- |
| `SUBSTRATE_METRICS_HISTORY_SERIES` | `core` | `core` or `extended` (any case, trimmed). `extended` makes the sampler write and `/slo/history` serve the 8 extra series; any other non-empty value is `core` with one boot warning that names the variable and quotes nothing. Has no effect while `SUBSTRATE_METRICS_HISTORY` is not `on`. | Unset or `core`, restart. Stored extended rows expire on the table's TTL. |

Consumers: read only by `loadConfig` (`loadMetricsHistorySettings`) in
`packages/mcp-server/src/config.ts`, so only the `substrate-mcp` unit (via
`/etc/substrate/substrate.env`) sees it. No per-unit spelling; not list-valued.

## Not `.env.example` lines

`SUBSTRATE_DASHBOARD_URL` and `SUBSTRATE_DASHBOARD_BEARER` are names the generated
provisioning example interpolates from **Grafana's own** environment. The substrate
never reads them, so they do not belong in `.env.example` (and a bearer value must never
be committed). They are documented in `docs/dashboards.md` § Operator steps.
