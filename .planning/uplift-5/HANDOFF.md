## What the operator does next

1. **Deploy uplifts 3, 4 and 5 together** as before: tag on `main`, then `SUBSTRATE_HEALTH_TOKEN_FILE=/etc/substrate/tokens/omp infra/vps/deploy-release.sh <tag>`. `deploy-release.sh` now runs the preflight first (report mode: it prints a table on stderr and always continues). To see it earlier: `bun run deploy:preflight <release-dir>` — on this host it reported config accepted, no state-file problems, and three unit-drift warnings that are exactly the pending uplift-4 unit changes (`MemorySwapMax=0`, slice `CPUWeight`/`IOWeight`). `SUBSTRATE_DEPLOY_PREFLIGHT=enforce` refuses before the swap on any error finding; `SUBSTRATE_DEPLOY_GATE=report|enforce` runs the boot gate first (needs docker, the local `postgres:16` and `greptime/greptimedb:v0.14.4` images and free disk; it never pulls). Rolling back is code-only — read `docs/runbooks/rollback-compat.md` first (disable the new archive timers and any watchdog drop-in before rolling back to `9231f43`).
2. **Reinstall the uplift-4 unit files** (`substrate.slice`, `substrate-mcp.service`; `daemon-reload`, restart, `bun run doctor:runtime`) — still pending from uplift 4, and the first thing the preflight reports.
3. **Optionally harden the units** (U5-2): per unit, run the transient `systemd-run` test in the example's header (it uses a throwaway `StateDirectory`; never `StateDirectory=substrate`, which re-applies mode 0755 to the audit-chain directory), then copy the drop-in, `daemon-reload`, restart, `bun run doctor:runtime`. Class A units first. The archive units fail their transient test with 226/NAMESPACE until their mount exists — by design. `docs/runbooks/vps-hardening.md`.
4. **Switch policies on evidence** (U5-7): after a soak in shadow, `bun run advisor:promote` (with `SUBSTRATE_URL` and a bearer in the environment) prints `ready | hold | insufficient-data | series-unavailable` for budgets, cache SWR, brief profile, brief recall and memory expiry. The extended evidence series need `SUBSTRATE_METRICS_HISTORY=on` and `SUBSTRATE_METRICS_HISTORY_SERIES=extended` (decide the Greptime volume size first: 500 MB in one record, 5 GB in another). `docs/runbooks/flag-promotion.md`.
5. **Dashboards** (U5-6): set `SUBSTRATE_METRICS_HISTORY=on`, give Grafana its own surface token (the substrate has no read-only token; the bearer carries that surface's full authority), install the Infinity plugin, copy `infra/vps/dashboards/provisioning/*.example`, import the two dashboards. `docs/dashboards.md`; never rendered in a live Grafana yet.
6. **Request path** (U5-3): `SUBSTRATE_BRIEF_GRAPH_READ=lite` and `SUBSTRATE_CACHE_BUMP_SCOPE=narrow` each one env var and a restart; compare `graph.brief` against `graph.get` durations and brief misses per accepted write. `docs/data-planes.md` states the staleness bounds.
7. **Durable events** (U5-4): enable server `accept` first (`SUBSTRATE_EVENT_IDEMPOTENCY=accept`, restart, confirm `/healthz` reports `idempotency: "accept"`), then `SUBSTRATE_EVENT_SPOOL=on` per collector env file; run `EXPLAIN` of the lookup against the production ledger before ever using `enforce` (the cost on the production image is unmeasured). Proven here against a scratch ledger: three emits while the ledger was frozen returned in 1.5 s, were parked, and a later `substrate spool flush` delivered each exactly once; replaying three events whose reply was lost left exactly three rows.
8. **Skills governance** (U5-5): `report` on the server and on the skills-sync unit, soak, approve every skill already on the library's main (`skills_approve` binds a PR to a skill by its proposal branch or by a change to exactly `<name>/SKILL.md`; a skill with no PR at all cannot be approved through it — an operator decision), wait for the `skills.sync` unapproved warning to stop, then `enforce` on the skills-sync unit. `docs/runbooks/skills-governance.md`.
9. **Optional CI boot gate**: `gh variable set BOOT_GATE --body true` (with `CI_ENABLED`). It starts docker containers on the shared runner and the host is at 94 % disk, so decide that first; a cancelled run can orphan a twin after SIGKILL (`docs/ci.md` has the sweep command).

## Rollback

Every item is a flag, an uninstalled file or a script nobody runs: unset `SUBSTRATE_DEPLOY_PREFLIGHT`/`SUBSTRATE_DEPLOY_GATE`, delete the sandbox drop-in, `SUBSTRATE_BRIEF_GRAPH_READ=full`, `SUBSTRATE_CACHE_BUMP_SCOPE=legacy`, `SUBSTRATE_HEALTHZ_INDEX_CAPACITY_MEMO_S=0`, `SUBSTRATE_EVENT_IDEMPOTENCY=off`, `SUBSTRATE_EVENT_SPOOL=off`, `SUBSTRATE_SKILLS_GOVERNANCE=off`, `SUBSTRATE_METRICS_HISTORY_SERIES=core`. The registry table, stored `_ik` payload keys and spool files are inert while the flags are off; nothing is dropped or unlinked by code.
