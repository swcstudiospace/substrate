# 46-PLAN: RAGFlow hybrid retrieval with Hindsight and Greptime context

## Units (disjoint files)

### U1 — hybrid knobs (RAGFlow plane and config)

Files: `packages/mcp-server/src/planes/ragflow.ts`, `packages/mcp-server/src/planes/ragflow.test.ts`, `packages/mcp-server/src/config.ts` (the RAGFlow settings only), `packages/mcp-server/src/flag-registry.ts` (new rows only), `.env.example` (new lines only).

- Add `SUBSTRATE_RAGFLOW_VECTOR_WEIGHT` (number in [0, 1], default 0.3) and `SUBSTRATE_RAGFLOW_RERANK_ID` (string, default unset). Parse them in the same style as the existing RAGFlow settings; an out-of-range weight is a config error with the variable named.
- `retrieveChunks` sends `vector_similarity_weight` from the setting. It sends `rerank_id` only when the setting is set.
- Tests in `ragflow.test.ts`, using the existing `RagflowFake`: with weight 0.7 and rerank id set, the captured body carries both; with defaults, the body carries 0.3 and no `rerank_id`; an out-of-range weight throws before any request.

Acceptance: the hybrid tests pass; the default body is unchanged from main.

### U2 — context augmentation (docs search path)

Files: `packages/mcp-server/src/docs-search.ts`, `packages/mcp-server/src/service.ts` (the docs search functions only), `packages/mcp-server/src/mcp.ts` (the `docs_search` tool block only), and the docs search test file(s) that already exist for these functions.

- `docs_search` input gains `context: z.boolean().optional()`. The service passes it through.
- With `context: true`, after the chunk path has produced its reply: call `recallMemories` with the question under `searchRecallBudgetMs`, keeping up to 3 hits, text cut to 400 characters; call `greptime.readEvents('session_id', session)` under a 1000 ms budget, keeping the last 5 rows reduced to `id`, `ts`, `kind`, `surface`, `summary` (cut to 200 characters). Attach `context: { memories, events, degraded? , untrusted }`.
- A missing session gives `events: []` with `degraded: 'no-session'`. A recall or ledger failure or timeout drops that source with a reason. The chunk path is never delayed past its own budget by context work; context runs after the chunks are ready, in parallel with nothing that can change the chunks.
- `searchReplyStorable` refuses any reply with a `context` key.
- Tests: no `context` key without the flag; with the flag, memories and events come from fakes; no session gives `no-session`; a recall failure keeps the chunks and sets a reason; a context reply is not stored in the cache.

Acceptance: the context tests pass; a reply without the flag is unchanged.
