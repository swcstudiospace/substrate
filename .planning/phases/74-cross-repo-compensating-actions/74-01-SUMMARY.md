# Phase 74 Plan 01: Summary

**Status:** implemented and verified locally, including against a live Postgres 16 in a disposable container. Not pushed. Route exposure is deliberately not part of this phase (D74-10).

## 1. What changed

New

Request validation (`parseBranchFanoutRequest`), the canonical fingerprint, the store port `CrossRepoStore`, the step and undo logic over `scopedGit`, the driver, `runBranchFanout` and `crossRepoStatus`. ## 2. Decisions

See `74-CONTEXT.md` D74-01 to D74-12. In short: branch fan-out is the operation; Postgres tables via step 43; every git call through `scopedGit`; caller key plus fingerprint for idempotency; step state persisted before each effect and outcome read from the ref; create-only and compare-and-delete; statuses `done`, `rolled-back`, `needs-attention`; no route.

## 3. Defects found and fixed while verifying

- **Adoption of a pre-existing ref.** The first draft adopted any ref already at the planned sha. A branch an outside actor created at the base commit would then have been deleted by the undo. Adoption is now limited to re-entry of a step already `applying`, where the create may have landed. Test: "a branch that already sits at the planned sha is not adopted".
- **Postgres array binding.** `state = any(${array})` fails: bun's driver does not bind a JS array there. Found only by the live run. Now `state = any(string_to_array(${joined}::text, '|'))`, the pattern `index-sweep.ts` uses. The fake could not have caught this, which is why the contract runs against both.
- **Rollback-compat runbook.** A new migration step must be named in `docs/runbooks/rollback-compat.md`. Found by the broader narrow run, not by the cross-repo tests.
- **Style rule.** A single-use one-line predicate was inlined.

## 4. Remaining gates for the operator

1. No HTTP route or MCP tool exposes the operation (D74-10). Adding one needs admission classification and a gate decision.
2. Migration step 43 must be rehearsed on a restored dump before production, like steps 33 to 42.
3. Concurrent drivers are safe by compare-and-set and the create-only ref, not by a lease (D74-09). A lease is not needed for the current single-caller shape; it becomes necessary once a route invokes the operation from several places.
4. The tree also has untracked `scripts/docs-migrate.ts` and `scripts/docs-migrate.test.ts`, which fail `bunx tsc --noEmit` (unused identifiers). They are not part of this change and were left alone.

## 5. Out of scope

- Production stores, Railway, systemd, /etc, and any live repository. Tests used temporary git repositories and a disposable Postgres 16 container, which was stopped afterwards.
- The git-hook install loop robustness observation in ROADMAP (separate).
