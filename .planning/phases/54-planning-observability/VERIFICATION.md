## Residual risks

- **Trigger scope (SC1, still holds).** A transition record is written only when a scan detects a planning-document change (`observer.ts:227-228`, `observer.ts:238`, `observer.ts:257`, `observer.ts:265`). A session-view or index-state move with no document change writes nothing. The phase id is fixed to `"planning"` (`observer.ts:40`), so transitions are not labelled per phase number.
- **Identity absent from GreptimeDB (SC1).** The metric row carries `outcome` only (`telemetry.ts:94`). The transition's `from` and `to` are on the stdout line only (`telemetry.ts:133-134`).
- **Single-flight delay (SC1).** A change that lands during a shared scan is recorded by the next scan, one tick later (`observer.ts:156`, `observer.ts:227-238`). It is not dropped, but it is delayed by up to one scan interval.
- **Partial diffs (SC1).** `unpublishedOutcome` counts added and changed paths only (`observer.ts:332-334`). Removals in an incomplete diff are not counted.
- **Shutdown bound (SC1).** Records still in flight after `SHUTDOWN_TRANSITION_MS` (`index.ts:202`) may not be delivered before exit. Past `MAX_PENDING_TRANSITIONS` (`observer.ts:61`), a record goes to the fallback alone (`observer.ts:285-286`).
- **LOADING unreachable (SC2).** Only `deriveSessionState` returns LOADING (`states.ts:47`); no caller passes `loaded: false` (`read.ts:189-197`).
- **Greptile P2 test (SC1).** The test for the "directory failures hide transitions" finding is `observer.test.ts:691-702`. It asserts `outcome: "refused"` and `incomplete: true`, with no published events, against `unpublishedOutcome` at `observer.ts:331-334`. I read it and did not run it.
