<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Linear labels/issue text → dispatcher | Anyone who can label an issue in the team can ask for an agent; issue text is untrusted. |
| dispatcher → filesystem and git | graph_id and repo slug become a path and a branch name. |
| dispatcher → Hermes child process | A model session with terminal/file tools starts on this host. |
| substrate.env → dispatcher process | The dispatcher's environment holds every substrate secret. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|

Residual (Hermes reading the issue via its Linear tool) is inherent to "then work" (D-13) and bounded by those controls. |
| T-02-04-02 | Tampering | Path traversal / git ref injection via graph_id or repo slug | high | mitigate | GRAPH_ID_RE plus explicit rejection of '..' and '.lock'; resolved worktree path must sit directly under /var/lib/substrate/worktrees; repo path must sit directly under /root/src/repos with an origin URL containing the slug; argv lists only, never shell=True. |
| T-02-04-03 | Information Disclosure | Secrets inherited by the Hermes child | high | mitigate | child_env allowlist (HOME, PATH, LANG, LC_ALL, USER, LOGNAME, SHELL, TERM) drops LINEAR_API_KEY, NOTION_API_KEY, SUBSTRATE_PG_URL and GREPTIME_*; a test asserts the drop; `/usr/local/bin/hermes` also unsets PYTHONPATH. |
| T-02-04-06 | Denial of Service | Disk exhaustion from worktrees | medium | mitigate | ensure_worktree refuses under 5 GiB free on / before any git call (D-12). |
| T-02-04-SC | Tampering | pip/uv installs | low | accept | No installer runs; httpx 0.28.1 and pytest 9.1.1 are already in the system python3 (verified during planning); Task 1's verify fails if a .venv or uv.lock appears. |
