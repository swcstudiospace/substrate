## Residual risks

- Criteria 2 and 4 are PARTIAL by their wording, by design: a reply can omit the root, and a root can go unrecorded (shutdown before the timer, a ledger refusal with no later change). `GET /corpus/root` always answers the live manifest, so a root that was never recorded reads `unanchored` and cannot be told apart from one waiting for its hour.
- Every anchor classification is tested against fake readers. `verifyEventRef` against the real ledger and devnet is covered by the checkpoint verification of earlier phases, not by this phase's tests.
- Offline `verify` does not authenticate the tree size; only `--online` compares it with the recorded event's count (`conflictWith`, `"a mismatch, or a recorded root event with another document count, makes the result invalid"`).
- The last stored root is held in memory: a restart can store the current root once more.
- The proof covers `(repo, path, sha256)` only, not the document text, the docs plane or the other manifest columns (`docs/corpus-proofs.md`, "What the root covers, and what it does not").
- A manifest over 100,000 active rows has no root and no proof (`root.test.ts` `"a manifest too large for a root is not emitted and says so on read"`).
