# Phase 72: Repo allowlist and scoped credentials - Plan 01

**Branch:** gsd/v18-p72-repo-allowlist (stacked on phase 71)
**Goal:** a session addresses only the repositories on its allowlist, and a credential scoped to one repository cannot read another repository's worktrees or corpus.

## 2. Threat model

- **Subject.** A caller is one of: a bearer-authenticated surface on REST or MCP (`callerSurface`); an anonymous caller when `SUBSTRATE_ALLOW_ANONYMOUS` admits one (`callerSurface` null); or the local CLI, which posts and runs git as surface `claude-code` (`packages/cli/src/worktree/command.ts` line ~287) under the same OS account as the host.
- **What the credential may reach.** The repositories its surface is granted by `SUBSTRATE_REPO_SCOPES`. A scoped surface reaches only those repositories' worktree rows, corpus rows, live-session metadata and checkouts. An unlisted or anonymous caller reaches none.
- **Assets.** Worktree registry rows (paths, branches, changed-file names), corpus rows and proofs, live-session private directions, and the git repositories on the host.
- **Threats.**
  - T1 path escape: a path reaches another repository through `..`, a symlink, or a worktree whose registry root is inside another repository. Mitigation: `realpath` on the target and on every registered root before containment; registered roots of two repositories may not overlap (boot refusal).
  - T2 name spoofing: a caller names repo A and passes a path of repo B. Mitigation: the repository is taken from the registry entry that contains the resolved path; the named repository must equal it.
  - T3 unscoped listing: a scoped caller omits `repo` and gets every repository's rows. Mitigation: the store filters to the granted set in the query, not after the read.
  - T4 git discovery escape: `git -C` walks up to an enclosing repository outside the scope. Mitigation: the scoped executor sets `GIT_CEILING_DIRECTORIES` to the parent of the registered root.
  - T5 fail-open config: a malformed or unknown-surface scope variable silently grants nothing or everything. Mitigation: boot refuses (ConfigError); unset means off, which is today's behaviour.
- **Refusal record.** One `repo.scope-refused` event through the existing emit path, with `surface`, the route or tool name, the reason code, and `requested_sha256`: the first 16 hex of SHA-256 over the requested repository or path. It never stores the raw path, the body, or a token. Refusal is fail-closed when the event cannot be written: the refusal response is still returned, and the write failure is reported on stderr in the CLI.
- **Out of scope.** Same-OS-account compromise. A credential that is not a surface bearer (per-repository secrets) is not introduced here. See Decision D72-03.

## 3. Decisions

- **D72-01 Registry.** `SUBSTRATE_REPO_REGISTRY` is a JSON object: `{"owner/name": {"checkouts": ["/abs"], "worktrees": ["/abs"]}}`. Keys are canonical `scopeRepoId` form. Entries are absolute; they are resolved with `realpath` at check time, not at boot, so a directory created later is recognised. Overlap between any two repositories' directories is a boot refusal. Unset means an empty registry.
- **D72-02 Scopes.** `SUBSTRATE_REPO_SCOPES` is a JSON object: `{"<surface>": ["owner/name", ...]}`. Unset means scoping is off and every surface may address any repository, which is today's behaviour, with a boot warning. Set means enforcement: a surface missing from the object, and every anonymous caller, gets an empty grant. A key that names no surface in `SURFACES` is a boot refusal.
- **D72-03 Credential.** The scoped credential is the existing surface bearer plus its grant. A repository-scoped credential means a surface granted exactly one repository. No new secret type is added. Per-repository secrets would need a token class and a rotation story; that is a decision for the owner and is recorded as an open risk.
- **D72-04 Gate before git.** The gate is pure given `realpath`. Every git spawn in scope is preceded by the gate; the executor spawns only after the gate returns ok. Tests inject a runner and assert zero calls on refusal.
- **D72-05 Enforcement points.** Gated at the service layer so REST and MCP share one decision:
  - `Substrate.driftScan` (takes `callerSurface`; returns a refusal instead of a report when refused).
  - `Substrate.listWorktrees` (store filter by granted repos; a named repo outside the grant is refused).
  - `corpusProofReply`, `corpusPlanReply`, `corpusIngestReply`, `corpusReconcileReply` (each entry's repo is checked after parse and before any manifest or plane read).
  - `corpusStatusReply`: a scoped surface is refused (`repo-not-granted`) because status is one cross-repository count. The unscoped behaviour is unchanged.
  - Live session issue in `Substrate.updateLiveSession` before `authority.issue`: the requested `repo_id` must be granted.
  - Corpus root and anchor are not gated: they are digests over all repositories and reveal no content. Recorded as a decision, not an omission.
- **D72-06 CLI.** `substrate worktree` runs as surface `claude-code` and reads the same two variables from its own environment. Under scoping, every root must be a registered `worktrees` directory of a granted repository, `--repo` must resolve to a granted repository, and `provision`, `merge-back` and `guard` path arguments must resolve inside a granted entry. Each refusal happens before any git call and exits 2 with a reason.
- **D72-07 Executor for phase 74.** `repo-executor.ts` exposes `authorizeRepoPath`, `authorizeRepo`, and `scopedGit(scope, identity, target, args, runner)`. `scopedGit` runs the gate, then the injected runner with `cwd` = the resolved registered root and `GIT_CEILING_DIRECTORIES` set. Phase 74 calls `scopedGit`; it does not re-implement checks.
- **D72-08 Flags.** New variables get rows in `packages/mcp-server/src/flag-registry.ts` with `documented: true`, and lines in `.env.example`. Behaviour defaults to today when both are unset.

## 5. Tests (behaviour, not source text)

Criterion 1 (boundary: API):
- `POST /drift` and MCP `drift_scan` with a path of a non-granted repository: refused; the injected git runner records zero calls; no event other than the refusal audit is written.
- A path that resolves through a symlink into a non-granted repository: refused.
- Path that escapes with `..`: refused.

Criterion 1 (boundary: CLI):
- `worktree provision --repo DIR` with DIR in a non-granted repo: exit 2, runner zero calls.
- `worktree list --root DIR` with an unregistered root: exit 2, runner zero calls.
- `merge-back PATH` outside grant: exit 2, zero calls.

Criterion 2 (two repositories A and B, a credential for A):
- `listWorktrees` with no filter returns only A rows; with `repo=B` refused; the store fake records that B was not read.
- `corpusProofReply` for B refused before the store is queried.
- `corpusIngestReply` with an entry for B refused before manifest or plane access.
- Live session issue for B refused before `authority.issue`.

Config and executor:
- Malformed JSON, unknown surface, overlapping registry roots: ConfigError.
- Unset scope: current behaviour (a fixture test that gate returns ok for any repo).
- `scopedGit` ceiling variable is set to the parent of the root.

Each test names its boundary in its title.

## 8. Follow-up: repository-keyed reads outside git, worktree and corpus (decision per route)

Rule: under scoping, a named repository must be granted, and an unnamed request is refused where its reply can span repositories. Refusal happens before the store, Hindsight or ledger read. Gate: `Substrate.scopedRepoRefusal` (`service.ts`). Refusal audit: `repo.scope-refused` with the route name.

Gated (decision by reply fields read in code):
- Live session discovery, `listLiveSessions` / `listVisible`: reply `sessions[]` carries `repo_id`, `surface`, `state`, `session_id` per session. Gated inside the live call before `listVisible`; a refusal answers `not-found`.
- Brief, REST `POST /brief` and MCP `memory_brief`: reply `detail` carries repo-keyed worktree overlap rows and session sections. Gated at both doors before `briefConditional`.
- Memory recall, REST `POST /memory/recall` and MCP `memory_recall`: reply `results[]` is Hindsight text recalled for `repo`. Gated at both doors before `recallMemories`.
- Session context, REST `GET /session/context` and MCP `session_context`: reply `items[]` carries `session_id`, `surface`, `state` for `repo_id`. Gated at both doors before `sessionContext`.
- Handoff, REST `POST /handoff` and MCP `handoff`: writes a packet whose `repo` is the request's, or the graph's when unnamed. Under scoping a named granted repo is required, so no default reaches a graph of another repository.

Not gated, with reasons:
- `handoffsForGraph` / `graph_get` and brief `graph_id`: keyed by graph id. The repository is known only after the graph is read, so no refusal can precede the read. Open.
- `docs_search` Hindsight fallback (`hindsightRagFallback` calls `recallMemories({query}, callerSurface)` unnamed): reply chunks are not repo-keyed and the call has no repo. Open: a scoped caller can receive memory from other repositories through docs_search.
- Found, not assessed: `memory_search` (`request.repo`), `memory_verify` (`repo`), `events_query` (repo filter), `graph_register` and `events_emit` (repo writes), `reapExpiredLeases(repo)`. Open until each is read.

Tests: `repo-scope.routes.test.ts` (one boundary test per gated REST route, asserting 403, no Hindsight call, no ledger read or write apart from the refusal audit; MCP doors share the same gate and have no HTTP test; live discovery is tested at the gate method, not through the live call).

## 9. Criterion 2 close-out (decision per item, evidence from the code)

1. Docs (REST `POST /docs/search`, MCP `docs_search`, REST `POST /docs/lightrag/query`, MCP `docs_lightrag_query`): refused to every scoped surface, named or not, by `scopedDocsRefusal` before any cache, retrieval or Hindsight fallback. Evidence: the reply fields (chunks from RAGFlow datasets and LightRAG) carry no repository to filter on, so no grant can be expressed. Tests: `repo-scope.reads-writes.test.ts` "docs search is refused...".
2. Graphs (MCP `graph_get`, MCP `handoffs_for_graph`, brief `graph_id` on REST and MCP): `graphRepoOf` reads only the graph row (`index.getGraph(...).repo`) to resolve the repository. Not granted: `repo-not-granted`. No resolvable repository, or no index: `graph-repo-unresolved`. Content is read only after the gate. Tests: "a graph whose repository is not granted...", "no resolvable repository", "a brief that names a granted repository but a graph of another repository".
3. Ledger and memory reads: `events_query` (MCP and `POST /events/query`) calls `queryEventsFor`. A named ungranted repository is refused before the ledger query. Otherwise rows whose repo is not granted, and rows with no repo, are dropped before the reply (`rowsInGrant`). The store query runs before the drop; the drop is before the reply. `memory_search` (MCP, paged and non-paged) gates a named repo, then `memoryReplyInGrant` drops entries whose `repo:` scope is not granted, `graph:` scopes whose graph is not granted, the graph links of ungranted graphs, and each entry's causal chain (not repo-keyed). `memory_verify`: the reader's repo must be granted before the index is read; otherwise `not_found`, the reply's reader rule. Tests: "a named repository outside the grant...", "an unnamed query returns only rows...", "entries scoped to another repository...", "verifying an entry as an ungranted repository...".
4. Writes: `events_emit` (MCP, `POST /events`) and `graph_register` (MCP) are refused by `scopedWriteRefusal` before the write when the target repo is not granted; with no repo the graph's repo must be granted; with neither, refused. Tests: "an event or graph registration naming an ungranted repository...", "a write with no target repository...", and HTTP "an event naming an ungranted repository is refused before the ledger write".
5. Lease reaper: it touches other repositories. The index predicate is `graph_id in (select graph_id from graph_index where repo = $1)` with a null `$1` matching every graph, so an unnamed `reapExpiredLeases` reaches every repo. Under scope it reaps each granted repo in turn, and a named ungranted repo reaps nothing (audited). MCP passes the caller's surface. Test: "a named repository outside the grant reaps nothing...".

Not tested at the door: the MCP doors for item 3's `memory_search` and item 4's `graph_register` share the service gates above; their wiring is by code reading only.

## 10. Security review close-out: fixes and accepted residuals

Fixed in this pass: RS-07 (derived hits are filtered by the caller's grant at the merge, the recall fan-out and the reply; `visibleToCaller` checks the grant first, via `grantedToCaller`); RS-17 (an anonymous refusal writes one audit row carrying a keyed digest of the route or tool, never the request; the digest key is random per process).

Accepted residuals, deliberately unchanged, with the reason each is accepted:
- RS-05 index-layer check: every path that writes a graph reaches the index through the service, and the service check covers each of them. A second check in the index would duplicate it without closing a path.
- RS-15 boot warning: a blank `SUBSTRATE_REPO_SCOPES` already refuses the boot, so the case the warning would report is already a hard stop.
- RS-18 CLI symlink race: the CLI runs as the same OS account that owns the worktrees, so a same-account attacker already has the access the race would give. Closing the residual needs a directory file descriptor for each git run, which is a separate change.
