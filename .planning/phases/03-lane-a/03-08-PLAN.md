Surface every VM permission request to a human on Telegram and answer it only with that human's
tap (D-13). The owner creates a new, dedicated approval bot (the Hermes bot's update stream is
already consumed by the Hermes gateway, research Open Question 11); the host long-polls it for
callback queries, authorises the tap by chat and user, and calls rivet's `respondPermission`.

absent (requests stay pending, as in 03-03); then the owner checkpoint; then a live Bot API smoke
without any tap. The live Approve and Deny round-trip happens in the proof (03-10) on the real
dispatched session, as the orchestrator's proof contract requires.

with `sudo grep -c`; the host reads them through its unit's EnvironmentFile. No command prints
the token, a chat id, a user id or a callback payload.
