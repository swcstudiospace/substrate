## Residual risks

- TimescaleDB history table implementing `HistorySink` is still absent: only `InMemoryHistorySink` exists (`presence.ts:198`), append-only. A production adapter and migration remain operator-gated (CONTEXT D52-b, unchanged on main).
- Live checks against Dragonfly (TIME, SET EX retention, SCAN) and GreptimeDB ledger rows cannot run in-repo; they remain operator-gated.
- Retention arithmetic changed since the earlier record: the key lifetime is now the freshness window plus a margin derived from the window (`presence-dragonfly.ts:8`), not the former fixed 86400 s + 3600 s. The residual is the same in kind: a session silent past retention drops out of `planning_sessions`; the code still never deletes a key.
- Changed meaning of `active` (unchanged on main): a checkout heartbeats only in a scan that sees a complete change, so `active` means "changed a planning document within the freshness window", not "is alive". A quiet session reads `stale`.
- Stat-fingerprint reuse: a same-size edit within filesystem timestamp resolution after the previous scan keeps its stored hash until the next write changes ctime.
- Absolute path disclosure: heartbeats store `worktree: root` and `planning_sessions` returns it to any MCP caller.
- Process-local baseline and index cache: a restart resets both, so changes made while the process was down are not published.
