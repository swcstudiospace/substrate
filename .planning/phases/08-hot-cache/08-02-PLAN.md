<objective>
The owner half that creates the Dragonfly service shell on Railway, and the VPS half that makes the
TLS material Dragonfly will serve (D-01, D-02). Dragonfly never runs its default password-less,
plaintext command: the service starts inert (`sleep infinity`) so the TCP proxy exposes nothing until
08-03 swaps in the TLS start command.

Order matters: the certificate's SAN is the TCP-proxy domain, which exists only after the owner enables
the proxy; and the 100 ms per-call budget (D-03) is only meaningful if Dragonfly is close to the VPS
(planning measured ~97 ms ICMP RTT to the existing Railway Postgres proxy), so the RTT is gated before
any certificate is made.

Credential rule (the 05-02 pattern): the agent only counts lines and generates secrets straight into
0600 files; it never prints or reads back a key or the password. The owner copies them into Railway in
08-03.

Purpose: D-01 (CA, SAN, password), D-02 (image pin, region/memory/volume), D-03 (RTT feasibility), D-04
(env presence and undo route first).
Output: 08-02-TLS.md, /etc/substrate/dragonfly-tls/, RESTORE.d/08-02.md, the .env.example block.

<interfaces>
Railway (08-RESEARCH-CONTRACTS.md §6.5): for a Docker image the start command replaces ENTRYPOINT in exec form; env expansion needs `/bin/sh -c "exec …"`. The TCP proxy forwards raw TCP from `<domain>:<port>` to the internal port and does not terminate TLS; Railway injects RAILWAY_TCP_PROXY_DOMAIN / RAILWAY_TCP_PROXY_PORT. Regions are chosen per service.
Dragonfly v2.0.0 (§6.1–6.3): any `DFLY_<name>` variable that is not a flag is fatal (`DFLY_requirepass` is the flag; `DFLY_PASSWORD` is not); the image has no openssl, so certificates are made off-box; `--tls` needs `--tls_key_file` and an auth method (the password).
Bun (08-01-SPIKE.md): the client verifies the chain against the pinned CA and the hostname against the URL host; the CA/server profile below is the one the spike proved.
Certificate profile: EC P-256 keys (`openssl ecparam -name prime256v1 -genkey -noout`); CA self-signed, CN substrate-dragonfly-ca, 3650 days, basicConstraints critical CA:TRUE, keyUsage critical keyCertSign,cRLSign; server CSR CN=<proxy domain>, signed by the CA for 825 days with subjectAltName=DNS:<proxy domain>, basicConstraints=CA:FALSE, keyUsage=critical,digitalSignature, extendedKeyUsage=serverAuth. `openssl x509 -noout -ext subjectAltName` prints the header line then `    DNS:<domain>`.
</interfaces>
