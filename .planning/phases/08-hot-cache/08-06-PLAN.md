<objective>
The phase proof (D-09, ROADMAP Proof): repeated brief, docs and recall calls are served from Dragonfly
(hits, latency drops); then, with Dragonfly unreachable from the VPS, the same calls return the same
answers uncached, the brief inside its 1.5 s budget, and every tool still answers (SC4). The outage is
made client-side with DROP rules scoped to the proxy's addresses and port, behind a RESTORE route and a
dry-run-tested dead-man timer written first.

A black hole is the harder outage: an established socket goes half-open, so the first calls pay the
per-call race until the breaker opens (08-04's close-and-re-dial clears the socket). A refused port is
the easy case the unit tests already cover.

Attribution: /healthz counters are process-global and every agent prompt's hook calls POST /brief, so
hits are proven per key (a throwaway keyed script reads each probe key's existence, PTTL and read time; a hit
never rewrites a key, so its absolute expiry stays put, while a miss moves it) and global deltas are recorded
with ≥ semantics only.
Answer equality is checked on drift-robust projections — the brief's full text, docs `results`, recall
`results` without `score` — and a mismatch is classified against a direct source read before it counts
as a failure, because the brief carries global memory with relative times and recall scores move as
Phase 7 forwards new records.

Purpose: D-09; SC2 (brief inside 1.5 s with Dragonfly unreachable), SC4 (every tool answers, counters
visible); proof of D-07's policy in production.
Output: 08-PROOF.md (setup, warm, unreachable, recovery), RESTORE.d/08-06.md, the unblock script.
</objective>

Keys script (throwaway, keyed one-shot, /tmp/08-06-keys.ts, deleted at the end): imports briefKey, genKey and queryKey from cache.ts by absolute path, opens a pinned client like cache.ts does, takes a label, reads gen:repo:R and gen:graph:G, builds the proof brief key (surface omp) and the docs and recall probe keys with the scopes searchDocs/searchContext use, and prints, for each of the three keys (brief, docs, ctx), `<label>_<k>_exists=`, `<label>_<k>_pttl=` and `<label>_<k>_read_ms=` (Date.now() right after that PTTL reply) — never a value.
Hit predicate `expiry_stable(a, b)` — the only per-key hit test: both reads have exists=1 and pttl > 0, the call(s) between them started at least 1 s after read a, and |(b_read_ms + b_pttl) − (a_read_ms + a_pttl)| ≤ 250 ms, i.e. the key's absolute expiry did not move. A hit never writes; a miss re-SETs with a fresh TTL, which moves the absolute expiry by at least the 1 s gap; an expired or evicted key reads exists=0 (PTTL −2) and fails. Comparing raw PTTLs is not enough (a rewrite followed by a slow second read also shows a smaller PTTL).
Source script (throwaway, keyed one-shot, /tmp/08-06-source.ts, deleted at the end): reads the sources directly, no cache — composeBrief with IndexStore/GreptimeClient for the proof brief; docs through docs/search.ts searchDocs with the RagflowClient and dataset id resolved the way service.ts does; recall through recall/search.ts searchContext with the AgentmemoryClient built the way service.ts builds it (re-read both at execution) — and writes the brief text and `{"results": …}` JSON for docs and recall into 0600 files in the task's temp dir for the shell to project; it prints nothing else.
/healthz → { index, greptime, …, cache: { enabled, connected, hits, misses, bypasses } } (08-04).
MCP JSON-RPC over curl (05-PATTERNS § Shared Patterns); a tool reply with `isError: true` counts as an error.
Firewall: iptables/ip6tables 1.8.10 (nf_tables backend); rules go at OUTPUT position 1 with `-m comment --comment <TAG>`; Docker also manages rules on this host, so rules are only ever deleted by their TAG, never by flushing a chain.
