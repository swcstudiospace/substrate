<objective>
Deliver the brief into Grok Build through the only channel that works there.

`src/substrate/brief.ts` is already ported into this worktree, byte-identical in
shape to `claude-ultrathink`'s `fetchBrief`/`emitEvent`. It is **not wired** into
`hooks/uplift.ts`. The fetch is therefore trivial; the *delivery* is the real
work, and it carries a documented, verified blocker:

**Grok Build discards a `UserPromptSubmit` hook's stdout entirely.** There is no
`additionalContext`. Porting `claude-ultrathink`'s stdout injection verbatim
compiles, runs, raises no error — and silently never reaches the model. Under a
fail-open design that failure is invisible, which is why this plan treats the
delivery mechanism as its own first-class task rather than a line of the fetch.

Two more facts from the same source shape the code: Grok's stdin envelope is
camelCase and only `hook_event_name` and `tool_response` are aliased, so reading
`session_id`, `tool_name` or `tool_input` as written yields `undefined`; and
`bun` is not on Grok's hook PATH, which is `/usr/bin:/bin`, so a hook needs a
shim rather than a bare `bun` invocation.

The replacement channel is not invented here — it is **already proven live on
this host**. `/root/.grok/rules/ultrathink.md` is a working rules entry that
tells the model to read an XML spec from a plugin-data path, and the installed
plugin carries it in its own `rules/` directory. This plan applies that exact
shape to the brief: the hook writes the brief to a session file, and a rules
entry names the file.

Purpose: Phase 1 Success Criterion 4, the Grok Build share.
Output: a wired hook, a rules entry, a skill, an idempotent projector, tests.

**D-03 (CONTEXT.md D3) binds every verify in this plan.** This worktree carries a
pre-existing red test that belongs to another session's uncommitted work;
`origin/master` was verified clean. No task here may attempt to fix it, and every
gate compares the failure count and identity against `01-BASELINE.md` rather than
against zero.
</objective>

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
