<objective>
**The phase tracer.** This is the one `type="tracer"` slice in Phase 1: the
thinnest complete path from a live agent surface, through a new Python substrate
client, across the process boundary into `substrate-mcp`, and out into the event
store — wired end to end and verified with a real round trip, before any other
surface is expanded.

It leads the phase because it is the riskiest architecture to be wrong about
*and* the one every other Python-side plan copies. Plans 01-03 (eng-board) and
01-05 (Grok Bot connector) both replicate this exact shape — fail-open client,
redaction before emit, additive call site inside an existing handler. Proving it
once here, on a live install, means a dead end costs one commit rather than three
landed layers.

Scope is fixed by **D-01 (CONTEXT.md D1)**: Lane B's Hermes work is an
**additive** `/brief` call and `events_emit` injected into the existing
`on_pre_llm_call` path **without restructuring it**. The TypeScript-engine bridge
and the Kanban retirement belong to the separate "Ultrathink on Hermes" v1.0
milestone and are OUT OF SCOPE here. ROADMAP Success Criteria 1 and 2 as
literally worded are therefore **not achievable in this phase and this plan does
not claim them** — it is written against the re-scoped behaviour recorded in
`01-VALIDATION.md`.

Purpose: make Hermes the first surface that reads the brief and emits events.
Output: two new modules in `prompt_uplift/`, one additive call site, four tests.

Every file this plan writes is inside `/root/src/repos/hermes-plugin`, which
`/root/.hermes/plugins/prompt-uplift` symlinks directly. Each write is live the
moment it lands. Plan 01-01 established the undo.
