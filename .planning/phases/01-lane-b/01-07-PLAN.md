<objective>
Wire Omp to the substrate and put the brief into its autonomous discovery.

Omp has **no MCP registration for substrate-mcp anywhere on this host** — the
research checked `/root/.claude.json`, `/root/.pi` and every config file
mentioning port 7410 and found nothing. So this is two pieces of work, not one:
the client connection is itself a task, and the discovery call is inert until it
exists.

`01-PATTERNS.md` recorded this registration as "No Analog Found". **That is
superseded** — the analog was located while planning and is exact:
`config.ts` already carries a complete second-MCP-endpoint pattern for Greptile
(the `greptileMcp` block in the `UltrathinkConfig` interface, in `DEFAULTS`, and
in `loadConfig`), and `index.ts` already builds a `greptileEndpoint: McpEndpoint`
and a second `UltrathinkMcpClient` from it and threads that client into the swe
path. The substrate endpoint is the same shape with different values. No new
mechanism is needed and no spike is required.

Purpose: Phase 1 Success Criterion 4, the Omp share — `memory_brief` added to
Omp's discovery tools — plus the emit half of the phase GOAL, which Criterion 4
does not name for this surface. Criterion 4 asks only that Omp read. The phase
goal is that every surface reads **and emits**, and Omp emits nothing today, so
without the post-discovery `events_emit` added in Task 2 it would be the one
surface left write-only. The substrate client built in Task 1 makes that one
extra call rather than a separate effort.

Output: a `substrateMcp` config block, a second MCP client, one gated discovery
call, one emit call, and the repo's first `swe.test.ts`.

Note for verification, so a correct implementation is not later mistaken for a
bug: `runAutonomousDiscovery` is gated on `looksLikeImplementation(prompt)`.
The brief therefore arrives on implementation-shaped prompts, which is exactly
what "adds `memory.brief` to its discovery tools" names. It is the criterion as
worded, not a partial delivery.
</objective>

    Add a `substrateMcp` block to `config.ts` in all three places the
    `greptileMcp` block appears — the `UltrathinkConfig` interface, `DEFAULTS`,
    and `loadConfig`'s per-section read. Give it `url` defaulting to
    `http://127.0.0.1:7410/mcp`, `tokenEnv` defaulting to `SUBSTRATE_TOKEN`,
    `tokenFile` defaulting to `/etc/substrate/substrate.env`, and `prefixes`

    primary config's prefixes are `linear_`, `github_` and `greptile_`. Without
    substrate prefixes on the endpoint, `selectTools()` filters every substrate
    tool out and the discovery call in Task 2 becomes a permanent silent no-op —
    the exact failure mode a fail-open design hides.

    In `index.ts`, build a `substrateEndpoint: McpEndpoint` exactly the way
    `greptileEndpoint` is built, resolving its token from the configured env var
    and falling back to `parseEnvFile` on the configured token file. Construct a
    `substrateMcp` client from it, and thread that client into the swe path
    alongside the existing `greptile` client.
  </action>
