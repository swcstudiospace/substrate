<objective>
Retarget the engineering-board auto-ingest at the substrate, additively.

Today `handle_session_start`, `handle_tool_call` and `handle_finalize` in
`hooks_session.py` write into a local SQLite `work_unit_store`, which
`pipeline.py` classifies into Kanban and Linear work items. There is no substrate
awareness anywhere in that repo. This plan adds one forwarding call to each of
the three handlers so the same activity also lands as substrate events — an
expansion of the slice plan 01-02 proved, using the same fail-open client shape,
the same vendored redactor, and the same "new statements inside an existing
handler" discipline.

Purpose: the second half of **D-01 (CONTEXT.md D1)**'s Hermes story. D-01 scopes
Lane B to brief + events, and explicitly defers Kanban retirement. So this plan
**keeps** the `work_unit_store` write and **keeps** `hermes-linear-connector`'s
dispatch, comment mirroring and DoD gate entirely untouched — the research is
unambiguous that the connector already does exactly what the phase wants kept,
and the temptation to improve it while in the neighbourhood is to be resisted.

Output: a substrate client, a vendored redactor, three additive call sites, tests.

`hermes-engineering-board/src/hermes_eng_board/` is live for a non-obvious
reason: `plugin/hermes_eng_board/__init__.py` inserts `../../src` onto `sys.path`
and the venv carries an editable install, so an edit under `src/` reaches the
running Hermes plugin exactly as the symlinked `plugin/` files do. Plan 01-01
snapshotted `hooks_session.py` for this reason.
</objective>
