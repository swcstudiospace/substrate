<objective>
Give Muse Code the only brief channel it actually has, and an event path it does have.

Muse is a closed compiled binary. Its hook event set was extracted from the
binary's own embedded strings and contains exactly `SessionStart`, `PreToolUse`,
`PermissionRequest`, `PostToolUse`, `PostToolUseFailure` — **there is no
`UserPromptSubmit` and no `Stop` event**. That is a confirmed absence, not an
assumption, and it is precisely why the phase specifies a static
`.substrate/BRIEF.md` fallback rather than a live fetch. Do not spend any part of
this plan looking for a prompt-submission hook.

Muse does read `AGENTS.md` and `CLAUDE.md` as session context — confirmed from
the same string dump, including an `/init` command whose prompt text instructs it
to read those files specifically. So the reachable design is: a collector writes
a current brief into the repo, and the repo's `AGENTS.md` points the session at
it. This is Design 1 from the research, the one that requires no Muse-side code
and therefore carries no Muse-side risk, and it is what this plan locks.

Assumption A2 — whether a `SessionStart` hook's *output* reaches model context —
is deliberately **not** on the critical path. Design 1 does not depend on it.
But emitting events is a weaker requirement than injecting context: a hook only
needs to run, which is certain. So this plan also projects a Muse plugin whose
`PostToolUse` hook emits substrate events, verified with
`muse plugins hook test <plugin-id>:<hook-id> --fixture <path>` — a real
subcommand confirmed in the binary's own help output. That closes the "and emit
events" half of the phase goal for Muse without depending on A2.

Purpose: Phase 1 Success Criterion 4, the Muse share.
Output: a brief-writing collector, a Muse plugin projector, tests, a systemd unit.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| substrate-mcp → repo working tree | Brief text is written into files inside repos other sessions may be editing. |
| Muse hook payload → collector process | Agent-authored tool names and arguments cross a process boundary toward `/events`. |
| projector → Muse plugin cache | This plan installs executable hook code into another agent's runtime. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-06-01 | Tampering | `AGENTS.md` and repo working trees | high | mitigate | `SUBSTRATE_MUSE_REPOS` is required with no inferred default, so no repo is written to unless the operator names it; the `AGENTS.md` edit is an append-only block between literal markers and rewrites nothing outside them; Task 1 tests 2 and 3 pin idempotence and preservation. |
| T-01-06-02 | Information Disclosure | Brief text written to disk and tool payloads emitted | high | mitigate | `redact` from `packages/mcp-server/src/redact.ts` runs over brief text before it touches disk and over every hook payload string before emit; Task 1 test 6 pins it. No second redaction pass is written. |
| T-01-06-03 | Denial of Service | A Muse turn behind a slow substrate | high | mitigate | The hook script reuses the fail-open emit shape with a short timeout and never exits non-zero; the brief writer runs out of band in its own process and is never on a Muse turn's critical path. |
| T-01-06-04 | Repudiation | A brief that silently never reached the session | medium | mitigate | A `brief.delivered` event carrying repo and byte count is emitted per delivery, so non-delivery is distinguishable from "substrate had nothing to say"; Task 1 test 5 pins it. |
| T-01-06-05 | Tampering | Truncating a good brief on a failed fetch | medium | mitigate | A failed or empty fetch leaves the existing file untouched; Task 1 test 4 pins it. |
| T-01-06-06 | Elevation of Privilege | Installing hook code into Muse | medium | mitigate | The bundle is generated by a projector in this repo and reviewed as source, installed at `--scope user`, and explicitly approved via `muse plugins approve` rather than silently trusted; the hook performs one loopback POST and nothing else. |
| T-01-06-SC | Tampering | npm/pip/cargo installs | low | accept | No package-manager install runs. `muse plugins install` installs a bundle generated from source in this repo, not a third-party package from a registry. |
</threat_model>
