<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| planner/executor → `/root/src/repos` superproject | A `git` write run with the wrong cwd can sweep another session's uncommitted work into a commit. This has happened once already on this host (STATE.md "Lesson recorded"). |
| executor → running Hermes install | `/root/.hermes/plugins/prompt-uplift` is a symlink to the repo; a write is immediately live. This plan writes no such file, but it creates the artifacts every later plan relies on to undo one. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01-01 | Tampering | `git add` in `/root/src/repos` | high | mitigate | Task 1 enumerates every staged path literally, forbids `git add -A`/`.`, requires `git init` first so a stray add cannot reach the superproject, and requires reading `git status --short` after each commit. |
| T-01-01-02 | Denial of Service | Running Hermes sessions | high | mitigate | No task in this plan writes a symlinked-live file. The snapshot plus RESTORE.md in Task 2 is the recovery artifact every later plan depends on. |
| T-01-01-03 | Repudiation | Test baselines | medium | mitigate | Task 3 records measured counts AND failing-test identities, so a later "unchanged baseline" claim is checkable rather than asserted. |
| T-01-01-04 | Information Disclosure | `/var/lib/substrate/phase1-baseline/` snapshots | low | accept | Snapshots hold source files already readable at mode 0644 by the same root user; the directory inherits `/var/lib/substrate` permissions and adds no new reader. |
| T-01-01-SC | Tampering | npm/pip/cargo installs | low | accept | This phase runs no package-manager install task. herdr was installed out-of-band by the owner and verified live on this host per **D-02 (CONTEXT.md D2 addendum)**, so the package-legitimacy checkpoint it would otherwise require does not apply. |
