<objective>
Stand up the Lane B runtime collector: herdr's socket seam into the substrate.

**D-02 (CONTEXT.md D2 and its addendum)** settles both open questions this
depended on. herdr is **already installed and already verified live on this
host** — version 0.9.1 at `/root/.local/bin/herdr`, server running, socket at
`/root/.config/herdr/herdr.sock`. **There is no install task in this plan and no
install checkpoint**; the owner installed it out of band and probed the seam
directly.

That probe also corrected the official documentation in two ways that each cost
a debugging cycle if rediscovered, and this plan is written against the corrected
contract, not the docs:

1. **`id` must be a STRING.** Sending an integer id returns
   `invalid request: invalid type: integer 1, expected a string`. herdr's own CLI
   uses ids like `cli:api:snapshot`.
2. **`pane_id` is REQUIRED on a `pane.agent_status_changed` subscription**, not
   the optional filter the docs describe. Omitting it returns
   `invalid request: missing field 'pane_id'`.
3. Therefore **a wildcard agent-status subscription is impossible.** The
   collector must enumerate panes from `session.snapshot` and subscribe per pane,
   tolerate individual pane failures, and re-subscribe as panes appear. This also
   sharpens the known upstream issue where one unknown pane can fail an entire
   subscription: with per-pane subscriptions mandatory, pane churn is the primary
   failure mode.

Purpose: Phase 1 Success Criterion 3 — the herdr `events.subscribe` collector.
Output: a mapper, a socket collector, tests, a systemd unit.

The Unix-socket ND-JSON transport has no precedent anywhere under `packages/` —
grep finds no `createConnection`, `net.Socket` or `.sock` usage. The collector
*shell* has a precise analog in `grok.ts`; the transport half is genuinely new
and is built from the D-02 contract above.
</objective>

    Create `packages/collectors/src/herdr.ts`.

    Reuse from `grok.ts` verbatim: the `loadOffsets`/`saveOffsets` shape for
    cursor state that survives restarts, the fail-open `emit()` POST to `/events`
    with the bearer header and timeout, and the `--once`/`--watch` CLI convention
    so the systemd unit stays uniform with the grok collector's. Point the state
    file at `/var/lib/substrate/herdr-offsets.json` via
    `SUBSTRATE_COLLECTOR_STATE`.

    Build the transport with `node:net` `createConnection` against the socket path
    resolved as: `--session` argument, then `HERDR_SOCKET_PATH`, then
    `HERDR_SESSION` naming the per-session socket under
    `~/.config/herdr/sessions/`, then the
    default `~/.config/herdr/herdr.sock`. Speak newline-delimited JSON: one object
    per line with `id`, `method`, `params`; replies reuse `id` under `result` or
    `error`. **Every `id` must be a string** — an integer id is rejected by 0.9.1.
    Use ids prefixed `substrate:herdr:` so they are identifiable in herdr logs.

    Implement the documented race-free bootstrap in this exact order: open the
    `events.subscribe` connection first, wait for its `subscription_started` ack,
    buffer every pushed event that arrives from that moment, then call
    `session.snapshot` on a separate connection, install the snapshot, then apply
    the buffered events in arrival order. Lifecycle streams start at accept time
    and do not replay retained events, so any other order loses events.

    Subscribe **per pane**. A wildcard agent-status subscription is impossible on
    0.9.1 because `pane_id` is a required field, so enumerate `panes[]` from the
    snapshot and issue one subscription per `pane_id` for
    `pane.agent_status_changed`, plus the pane-scoped subscriptions for
    `pane.agent_detected`, `pane.output_matched` and `pane.exited`. Isolate each
    subscription: an `error` reply for one `pane_id` must be logged to stderr and
    skipped, never allowed to abort the others — one unknown pane failing an
    entire subscription is the documented upstream failure mode this design
    exists to avoid.

    Handle pane churn: on a `pane.agent_detected` for an unknown pane, and on a
    poll interval, re-fetch `session.snapshot` and subscribe any `pane_id` not
    already subscribed. Treat pushed events as invalidation triggers rather than
    as authoritative state — on any subscription error, socket error, or `end`,
    reconnect and re-run the full bootstrap including a fresh `session.snapshot`.

    Map each event through `mapHerdrEvent` with the pane record from the current
    snapshot, and `emit()` the non-null results. Record the last applied event
    cursor in the offsets file so a restart does not re-emit.

    Note for the record, not for implementation: after a machine restart herdr
    restores its layout but the original processes do not survive, so this
    collector is not the durability story — that is Phase 3 (Lane A).
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| herdr socket → collector process | Agent-authored terminal text crosses a process boundary in `pane.output_matched` payloads. |
| collector process → substrate-mcp | That text is forwarded as event summaries and payloads over loopback HTTP. |
| herdr 0.9.1 replies → collector state | Pushed events are treated as invalidation triggers, not as authoritative state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-04-01 | Information Disclosure | `pane.output_matched` terminal text becoming an event summary | high | mitigate | `mapHerdrEvent` runs `redact` from `packages/mcp-server/src/redact.ts` over matched terminal text before it becomes a summary or payload value; Task 1 test 4 pins it with a `tskey-` style token. No second redaction pass is written. |
| T-01-04-02 | Denial of Service | Observability loss when one unknown pane fails the whole subscription | high | mitigate | Per-pane subscriptions are mandatory on 0.9.1 anyway; each subscription reply is isolated so an error for one `pane_id` is logged and skipped. Task 2 acceptance requires other panes to keep emitting. |
| T-01-04-03 | Denial of Service | Event loss in the subscribe/snapshot race | high | mitigate | The documented race-free order is implemented explicitly: subscribe, wait for ack, buffer, snapshot, install, apply buffered. Reconnect re-runs the whole bootstrap with a fresh snapshot. |
| T-01-04-04 | Tampering | Stale pane state from trusting pushed event payloads | medium | mitigate | Pushed events are invalidation triggers; pane attribution comes from the current snapshot record, and any subscription error forces a re-snapshot. |
| T-01-04-05 | Spoofing | Anything with filesystem access to the herdr socket | low | accept | The socket is mode `srw-------` owned by the same root user that runs the collector; this plan opens no new listener and widens no permission. |
| T-01-04-06 | Elevation of Privilege | Collector process privileges | medium | mitigate | The unit inherits every hardening directive from the grok unit unchanged — `NoNewPrivileges`, `PrivateTmp`, `ProtectSystem=full`, `ProtectKernelTunables`, `ProtectControlGroups`, and a `RestrictAddressFamilies` list narrowed to AF_INET/AF_INET6/AF_UNIX. |
| T-01-04-SC | Tampering | npm/pip/cargo installs | low | accept | No install runs in this plan. herdr 0.9.1 was installed out of band by the owner and verified live per D-02, and the collector uses only `node:net` plus existing workspace imports. |
</threat_model>
