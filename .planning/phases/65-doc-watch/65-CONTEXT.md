# Phase 65: Doc Watch - Context

**Gathered:** 2026-10-29 (Run 14)
**Status:** Decisions fixed by the orchestrator from the Run 14 scout evidence; the owner's request is in `.planning/STATE.md` (Run 14).

## Phase boundary
Triggers, coalescing and the sync command that connect a documentation change to the phase 63 bulk path, with state that survives restarts. It does not decide what is worth retrieving.

## Decisions
- **D65-1:** four triggers feed one idempotent sync: git hooks, a filesystem watcher, the reconcile timer and the server's own planning events. Existing mechanisms: the post-commit collector is the only git hook that ships (`packages/collectors/src/install-git-hook.ts:16-17`, never overwrites a foreign hook, no debounce, emits the first 20 changed file names); the planning observer scans `.planning/` of one checkout every 15 s (`planning/observer.ts`, `planning/config.ts:22`); the server refresh runs only when `docsBackend === "lightrag"` (`service.ts:5651`).
- **D65-2:** the server's in-memory `planningHashes` is replaced by the manifest, so a restart re-ingests nothing unchanged.
- **D65-3:** `POST /docs/merge-trigger` has local sources for two datasets and nothing calls it for `agent-substrate` or `programming-desk` (`server.ts:353-361`, `:1736-1812`); it stays for skills sync, and the new path does not depend on it.
- **D65-4:** the VPS is private, so GitHub pushes cannot call it. A fetch moves refs and not the working tree, so a push made elsewhere leaves a checkout unchanged and a working-tree scan would keep reporting no change; and a fetch inside a user's clone writes into that clone's `.git` (remote-tracking refs, `FETCH_HEAD`, objects), which the default triggers must not do. The reconcile therefore fetches into a Substrate-managed blobless mirror (`git clone --mirror --filter=blob:none` once, then `git fetch` inside the mirror, under `SUBSTRATE_CORPUS_MIRROR_DIR`, never in the user's repository) and reads the mirror's default-branch tree directly (`git ls-tree -r` and `git cat-file --batch`); the mirror's remote URL comes from the checkout's own remote configuration, read-only, and a failed fetch leaves the mirror at its last successful state, which the sync keeps reading and reports as `mirror-stale`, so an offline sync never replaces newer indexed text with an older checkout and never uploads it again when the origin recovers; only a repository that has never had a mirror is read from its working tree alone. One view applies per repository per sync, decided from git state alone so the views never alternate on the same `(repo, path)` row: the mirror's default-branch tree is the base and the checkout's own documentation changes are laid over it path by path (a path whose working-tree content differs from the merge base, whether committed beyond it, uncommitted or untracked, takes the working-tree content; a path deleted locally is removed; every other path takes the mirror's content). A level or ahead checkout therefore sees its own tree, a behind checkout sees the remote's newer files plus its local edits, and a local edit never hides an unrelated remote update. A sync that finds the view equal to the manifest changes nothing. The tests include a remote-only push, a local edit together with an unrelated remote change (both must be visible), and an alternation of local edits and remote-only pushes without pulling that asserts the manifest follows with no flip-flop and no re-ingest of an unchanged file, and a success, failure and recovery sequence (a remote-only update indexed, the fetch then failing, then recovering) that changes no row while offline and none after recovery.
- **D65-5:** the default triggers write nothing into any repository: the watcher and the reconcile are read-only, and git hooks are an opt-in installer the operator runs for chosen repositories (a hook writes into that repository's `.git`). Hooks and the watcher never fail the user's command; hints are bounded and lost hints are recovered by the reconcile run, which also compares active manifest rows with the docs plane (the manifest and the plane are a dual write, so drift is detected, not assumed away). Staged units carry `Nice`, an idle I/O class, `CPUQuota` and `MemoryMax`, and the watcher falls back to sweep-only when the inotify limit is reached.
- **D65-6:** a new `docs.sync` event maps onto the existing `note` kind through `payload.action` with a row in `event-sources.ts` and the table in `docs/event-vocabulary.md`; the vocabulary lock stays unchanged. The existing `docs.planning` action has no row (`service.ts` only) and gets one.
