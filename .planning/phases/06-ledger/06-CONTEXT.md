# Phase 6: Ledger - Context

**Gathered:** 2026-09-26
**Status:** Ready for planning

<domain>
## Phase Boundary

Tamper-evident history: every event the substrate stores is hashed and globally chained on ingest, every closed hour of events is Merkle-rooted into a Solana devnet memo, and `substrate verify <graph_id>` checks both the chain and the on-chain roots.

ROADMAP success criteria:
1. **Re-scoped by D-01 (owner-approved, 2026-09-26).** "Every event is hashed on ingest over the canonical event JSON and carries `prev`." The original wording, "Every collector computes `hash` over the canonical event JSON and carries `prev`", is kept for the record. It follows the Phase 1 D-01 precedent: the orchestrator annotates ROADMAP in place and keeps the original text quoted.
2. An hourly systemd timer Merkle-roots the hour's events into a Solana **devnet** memo and records root, signature and event count in an `anchors` table.
3. `substrate verify <graph_id>` recomputes the chain and checks roots against signatures.

Proof: alter one event row, and `verify` flags the graph (D-12 defines the procedure, including the restore).

Depends on Phase 1 only. Phase 3 is blocked at 03-10 and Phase 4 is planned but not executed. Phase 6 must not change what those phases rely on in `substrate-mcp`: the `/events`, `/brief` and `/verify` request and response shapes, and the MCP tool names. Phase 4's 04-03 also edits `service.ts`, `service.test.ts`, `types.ts`, `server.ts` and `cli/src/index.ts`. Plans that touch those files must not run at the same time as 04-03.

Not in this phase:
- client-side hashing in any producer;
- re-chaining or anchoring the pre-cutover rows;
- mainnet or any paid RPC;
- per-event Merkle inclusion proofs;
- a global `verify --all`.

</domain>

<decisions>
## Implementation Decisions

### Hashing and the global ingest chain
- **D-01:** Hashing stays on ingest. `substrate-mcp` is the only writer of `agent_events` (`greptime.ts:144`, called from `service.ts:136`), and the hash is computed after redaction (`event.ts:52-91`). No producer changes. ROADMAP SC1 is re-worded to "every event is hashed on ingest" as an owner-approved re-scope, the same way as Phase 1 D-01. — **Reversibility:** reversible (wording only; the ingest path already hashes every row).
- **D-02:** **One global ingest chain.**
  - `emit` is serialized in-process with a promise mutex.
  - Every new event's `prev` is the hash of the event ingested just before it, across all surfaces.
  - The chain head is kept in memory and seeded from Greptime on boot.
  - `session_id` stays as metadata only. The per-session `lastHash` lookup (`greptime.ts:148-155`) stops being used.
  — **Reversibility:** reversible in code. Rows written under the global chain keep their global `prev`.
- **D-03:** The historical rows are **not** re-chained: 3,681 when this was decided, 3,796 when research ran, since events kept arriving. The global chain starts at a **recorded cutover event**, the first event written by the new code. Its id, hash and ingest time go into the phase evidence. The existing per-session verify stays valid for pre-cutover rows. — **Reversibility:** reversible.

### Anchor mechanism and key custody
- **D-04:** A **new dedicated devnet keypair** at `/etc/substrate/ledger-devnet.json`, mode 0600, owner root, generated by the agent with `solana-keygen`. Its path goes into `/etc/substrate/substrate.env` as `SOLANA_ANCHOR_KEYPAIR`, alongside an explicit `SOLANA_RPC_URL=https://api.devnet.solana.com`. `~/.config/solana/id.json` (5pSW…) and the Solana CLI's default config are not used and not changed. — **Reversibility:** reversible (remove the key file and the env lines; restore from the snapshot).
- **D-05:** The agent funds the key with `solana airdrop`. If the faucet refuses, a **checkpoint:human-action** asks the owner to fund it. — **Reversibility:** n/a (devnet SOL has no value).
- **D-06:** The memo is written by the Solana CLI alone, with no new npm dependencies: `solana transfer <self> 0 --with-memo … --url devnet --output json`. A spike confirms that devnet accepts a 0-lamport self-transfer carrying a memo. If it does not, fall back to a 1-lamport self-transfer. — **Reversibility:** reversible.
- **D-07:** An **hourly systemd timer** (`OnCalendar=hourly`, `Persistent=true`) runs `ledger anchor`.
  - It anchors every closed, not-yet-anchored hour older than a lag.
  - It skips empty hours.
  - It is idempotent via the `anchors` rows.
  - It exits non-zero on an RPC failure, so the next tick retries.
  — **Reversibility:** reversible (disable and remove the units).

### Anchors storage and the Merkle definition
- **D-08:** Anchors live in Greptime. The currently empty `anchors` table (0 rows, `PRIMARY KEY ("root")`, `greptime.ts:112-121`) is re-created **keyed by period**, not by root. — **Reversibility:** reversible while it holds no anchors; after that, anchors can be re-derived from the chain.
- **D-09:** Add an `ingested_at` column to `agent_events` (an additive `ALTER`). Hours are bucketed by **ingest time**, not by the client-supplied `ts`. — **Reversibility:** reversible before cutover (`DROP COLUMN`). After cutover, post-cutover rows depend on it.
- **D-10:** An **RFC 6962-style Merkle tree**: `0x00` leaf prefix, `0x01` node prefix, no duplicate-last. It covers event hashes ordered by `(ingested_at, id)`. Memo format: `substrate:v1:<period_start_iso>:<root_hex>:<count>`. — **Reversibility:** versioned by the `v1` tag; a later format would be `v2`.

### Verify and proof
- **D-11:** `substrate verify <graph_id>` is the existing chain check **plus** a per-hour anchor check. For every hour that contains an event of the graph:
  - recompute that hour's root and count from Greptime;
  - fetch the memo by `tx_sig`, server-side in `verifyGraph` with an RPC timeout;
  - compare the two.

  It reports the first mismatching hour. Recent unanchored hours report `pending`, not failure. The CLI stays a thin POST and keeps exit codes 0 and 1. — **Reversibility:** reversible.
- **D-12:** Proof procedure:
  1. Create a throwaway graph `ut-ledger-proof-<stamp>` with 3 events in one session.
  2. Wait until its hour is anchored.
  3. Overwrite the middle event with the same `(surface, repo, graph_id, kind, ts)`: (a) keeping the stale hash, which breaks the chain; (b) with recomputed hashes, which the anchor check catches. `verify` must flag both.
  4. **Restore** the original rows so the hour verifies again.

  The original rows are captured before any overwrite. — **Reversibility:** reversible (the restore is part of the proof).

### Resolved research open questions (orchestrator, 2026-09-26)
- **D-13 (OQ1):** Keep `OnCalendar=hourly` literally, with a 5-minute lag inside the job. An hour is therefore anchored at the second tick after it ends and stays pending for up to about 2 h. The proof waits for the timer. A manual `systemctl start` of the same unit is allowed only as a recorded fallback (`anchored_by=manual` plus a Gap). — **Reversibility:** reversible (change the calendar or the lag).
- **D-14 (OQ2):** An hour with no anchors row is `pending` until 3 h after it closes. After that it is unanchored, which counts as a failure. This is the threshold behind D-11's "recent unanchored hours report pending". — **Reversibility:** reversible (PENDING_MS).
- **D-15 (OQ3):** Before anchoring an hour that has no row, the job lists the key's recent memos. If a signer-checked v1 memo for that period exists, the job adopts it instead of re-anchoring. A memo whose root differs is recorded as found, logged as ALARM, and the job exits 1. This extends D-07's idempotency. — **Reversibility:** reversible (remove the adopt step).
- **D-16 (OQ4):** Verify fails closed. If devnet cannot be read, the transaction is not found, or `SOLANA_ANCHOR_PUBKEY` is unset, the hour is `unverified`: `ok:false`, the CLI exits 1, and it prints the distinct line `[substrate] verify could not check devnet for <period>: <reason>`. — **Reversibility:** reversible (downgrade `unverified` to a warning).

### Standing rules carried forward
- Two-sided test gates against a measured phase baseline (`06-BASELINE.md`). A failure that vanishes fails the gate just like a new one.
- Before editing any live file outside this repo (`/etc/substrate/substrate.env`, `/etc/systemd/system/*`, the new key file, the Greptime schema), take a snapshot under `/var/lib/substrate/phase6-baseline/` and add a `RESTORE.md` route. Read `/var/lib/substrate/phase1-baseline/RESTORE.md` before touching any Phase 1 snapshotted file.
- Stage by explicit path in this shared checkout; never `git add -A`. Commit messages carry `Refs SPE-3576`.
- Never print secrets. Probe `substrate.env` only with `sudo grep -c '^NAME='`. The keypair's contents and seed phrase are never printed or logged.
- Fail open for collectors: an unreachable Greptime or a chain problem must never block a producer.

### Claude's Discretion
Module layout within `packages/ledger` and `packages/mcp-server`, the lag value, the extra `anchors` columns, the verify response shape beyond `ok`/`events`/`brokenAt`/`reason`, and how the mutex is built. The research recommends the following; the planner may adopt them without the owner:
- `ts := ingested_at` for events with no client `ts`, and a strictly increasing `ingested_at`. Together they remove same-millisecond `last_row` collapses.
- A pre-insert duplicate guard for events that carry a client-supplied `ts`.
- Batching queued emits into one INSERT, because one Greptime round trip takes about 182 ms.
- Merkle leaves are **recomputed** content hashes. The anchor job flags any row whose stored hash differs.
- A non-secret `SOLANA_ANCHOR_PUBKEY` for the server. The verifier checks the memo transaction's signer against it.
- Matching every Memo program ID, not only `MemoSq4…`.

<specifics>
## Specific Ideas

- Live numbers (2026-09-26 probes):
  - `agent_events` holds 3,796 rows over 48 hours: on average 79 per hour, p50 66, p95 212, max 368.
  - Peak load: 7 events in one second and 38 in one minute.
  - Near-collision pairs under the same tags: 2 at ≤1 ms apart and 4 at ≤10 ms, all from herdr (server-assigned `ts`).
  - 0 rows have a future `ts`.
- `POST /verify` returned `{"ok":true}` for all 18 existing graphs (scout). This must stay true after cutover.
- The memo for a typical hour is 105 bytes; the whole transaction message is 258 bytes (offline sign-only build). One devnet memo transaction cost 5,000 lamports in fees (observed on a v4 memo transaction).
- Devnet's rent-exempt minimum for a 0-byte account is 650,240 lamports (`getMinimumBalanceForRentExemption(0)`).
- The public devnet RPC is flaky per method: `getAccountInfo` and `getFirstAvailableBlock` timed out after 15-20 s, while `getSignaturesForAddress`, `getVersion` and a retried `getTransaction` answered in 166-528 ms.
- Last recorded test baseline (04-CONTEXT, `9eef1ee`): bun test 338 pass / 0 fail across 22 files, tsc exit 0, dispatcher pytest 149 passed. Re-measure it for `06-BASELINE.md`.

</specifics>
