# 12-01: Runner-held substrate leases for swarm tasks

## Objective
Every swarm task is worked under a substrate lease that the runner holds for the executing agent, so two replicas never work one node and a dead replica's node frees itself (ADR 0001 S2 criteria 1-5 and 10, swarm side).

## Tasks
1. `swarm/substrate_client.py`: `mcp_call_outcome(tool, args, env, *, surface) -> Outcome(status, value, detail)` with status `ok | refused | error | unreachable | off`. `refused` = HTTP 401/403 or `isError` with `{"error": …}`; `error` = any other non-2xx or thrown error. `mcp_call_json` is rebuilt on it with identical results.
2. `swarm/substrate_tee.py`: `replica_id()` (`SWARM_REPLICA`, default `r0`, `[A-Za-z0-9._-]{1,64}` or `ValueError`) and `session_id(agent, graph_id)`, used by `build_event` and the lease bridge. `TYPE_KINDS` gains `lease.unleased`, `lease.refused`, `lease.lost`, `lease.unsettled` → `warning` and `lease.denied` → `note`.
3. `swarm/substrate_lease.py` (new): TTL from `SWARM_LEASE_TTL_S` (default 900, clamped to [30, 86400]), heartbeat at TTL/3. `LeaseBridge` with `acquire / lease_s / watch / beat / start / close / settle / rework`. `_call()` is the single token seam for Phase 14. Unknown nodes are registered as A01 and the claim retried once. The session refusal table is `SESSION_REFUSALS`; between rounds, `expired`/`unheld` re-claim. `notes.lease` is the mirror. `settle_mirrored()` serves `orch_status`.
4. `scripts/swarm_run.py`:
   - `run()` builds the bridge (not on `--dry-run`, not when off), validates the replica (E-INPUT), starts the keeper and closes it in `finally`.
   - `select_batch()` claims before dispatch, skips denied or refused claims without taking a slot, and stops the run with `waiting on leases` when nothing else can run.
   - `execute_one` passes the granted TTL as `lease_s`, maps `LeaseStopped` to FAILED with the table's reason, and settles in a `finally`.
   - `run_agent_headless(..., on_session=)` lets the keeper stop the session's process group.
5. `swarm/results.py` `reconcile(..., leases=None)`: `settle` after DONE (`graph_complete`) and after CHANGES_REQUESTED → ESCALATED (release); `rework` after CHANGES_REQUESTED → IN_PROGRESS (release + re-claim).
6. `scripts/orch_status.py --transition`: `settle_mirrored` after the transition (CANCELLED/FAILED/BLOCKED/ESCALATED release, DONE completes).
7. `tests/test_substrate_lease.py`: a fake substrate behind `substrate_client._open` with a simulated clock, CAS claims and the Phase 11 rules. It covers:
   - grant → dispatch with `lease_s` = granted TTL
   - denied → not dispatched
   - refused → not dispatched
   - unreachable → unleased and recorded
   - the refusal table: `lost`, `unheld`, `not-holder`; `expired` → re-claim; `expired` + denied → stop
   - a real keeper thread stopping a real session
   - DONE → complete; CHANGES_REQUESTED → release + re-claim with the rework reusing it; FAILED/CANCELLED → release
   - two replicas racing → one dispatch; a stopped heartbeat → the second replica claims at expiry and not before
   - unregistered node registered once
   - off and dry-run → no calls; the `mcp_call_outcome` classification
8. Docs: `docs/substrate-leases.md` (new). `docs/substrate-tee.md`: environment, type table, "Not in S1", the shared session builder.

## Out of scope
`coord_handoff` (Phase 13); per-agent env files and stripping child tokens (Phase 14); leasing the `orch_status --ingest` / in-session path; REST lease routes. The Task Store keeps every table and row (LEASE-09); the bridge adds `notes.lease` only.
