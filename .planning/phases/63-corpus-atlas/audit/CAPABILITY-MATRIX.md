- R7: the docs canary and `scripts/docs-golden.ts` give a fixed golden corpus and an alert on a changed failing set. Phase 70 adds a golden set derived from the corpus, scores and an offline harness.
- R2: the planning observer (`planning/observer.ts`) already detects planning changes for one checkout and emits `planning.changed`. Phase 65 replaces the in-memory refresh state with the manifest and adds other roots and repositories.
- R6: `metric_samples` (opt-in, with TTL) is the path for new docs series; `docs-freshness.ts` already raises `docs.freshness`.
- R8: the hourly anchor is the chain path. The corpus root only has to be a ledger event inside an hour.
- R10: `coord_handoff` already records signed packets; the gap is that nothing reads them into a session.
- R4: the session registry and directive inbox already enforce operator-only authorship, rate limit and audit-before-queue (`planning/steering.ts`); phase 67 keeps those.
