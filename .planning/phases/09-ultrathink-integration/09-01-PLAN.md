# 09-01: emit seam and hook wiring

## Objective
After `runPromptSubmit` plans a prompt and writes its session record, emit one fail-open `note` event carrying the Graph ID. The hook result must never depend on the substrate.

## Tasks
1. `src/substrate/brief.ts`: plan-event builder for `emitEvent`. Session id `<host session>:<graph id>` (per-graph chain, so the substrate's per-session hash chain never interleaves graphs). Payload: Graph ID, host, repo slug, branch, node count. Never prompt, spec or plan text. Nothing sent without a substrate URL or with `SUBSTRATE_DISABLED=1`.
2. `src/claude/hook.ts`: add `HookDeps.emit` seam (next to `HookDeps.brief`); call it from `runPromptSubmit` only, after a successful session write. `src/host/plan.ts` reaches the same function, so no second call site.
3. No emit for skipped prompts, fallback specs, unknown sessions or failed state writes. A rejecting or throwing emitter is swallowed.
4. Tests in `src/claude/hook.test.ts` and `src/substrate/brief.test.ts` for each case above, including identical hook result with a rejecting/throwing emitter.
5. Docs: `CHANGELOG.md`, `README.md`, `docs/privacy.md` (lists the request), `docs/configuration.md`, `docs/architecture.md`.

## Out of scope (deliberate)
- Graph registration from the hook. ADR keeps graph tools MCP-only; registration stays the kickoff skill's MCP step.

## Verification
- `tsc` clean; full test suite passes.
- Live: the `emitEvent` client is accepted by a running substrate-mcp and the note is stored under the same Graph ID.
