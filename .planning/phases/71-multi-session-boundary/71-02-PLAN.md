Wire names are fixed across 71-02/71-03:
- POST /steering/sessions body { repo_id, state? (default ACTIVE), steering?, planning_hash? }; no session ID or owner accepted for creation. Success { status: "issued", session_id, repo_id, state, updated_at, expires_at, session_binding }; proof is 64 lowercase hex characters, handle is ls_ followed by 64 lowercase hex characters.
- POST /steering/sessions/heartbeat body { session_id }; success { status: "renewed", session_id, expires_at }.
- POST /steering/sessions/close body { session_id }; success { status: "closed", session_id, closed_at }.
- Private REST requests use X-Substrate-Session-Binding, not body/query/argv proof. Add an optional sessionBinding parameter to the client methods directives/wait/heartbeat/close. Ordinary operator queue/ack bodies stay exactly as today; operators can use explicit server-side override without a private record, but the CLI cannot infer that role from the --surface string.
- Denial is precisely { status: "refused", error: { code: "not-found" } }, HTTP404; missing/wrong proof, foreign, unknown, expired and closed targets share it. Authority failure is { status: "refused", error: { code: "session-unavailable" } }, HTTP503. Principal limit is HTTP429 with bounded retry-after; operator-required remains its existing forbidden/403 only after a valid target-bound admission.
- GET /steering/sessions without targeted proof gives non-operators metadata only: session_id, surface, repo_id, state, updated_at, expires_at. Private steering/planning_hash/pending_directives are omitted, not fabricated as zero. Operator discovery may include those fields. Update guards/renderers to model their absence explicitly.
- Export CLI-local LiveSessionBindingRecord { version: 1, server_identity: string, surface: string, session_id: string, session_binding: string, expires_at: string }. server_identity is SHA-256 of the canonical configured base URL (no URL credentials/query/fragment; normalize trailing slash). Validate server identity, selected surface, exact handle, proof grammar and file shape before every use; an expiry in a local record is advisory, never server authority.
- binding-record.ts exports saveBindingRecord(record, options), loadBindingRecord(path, expected), bindingRecordPath(serverIdentity, surface, sessionId, options). Default private directory is homedir()/.local/state/substrate/live-sessions; avoid adding an environment reader or new token resolver. Deterministic filename is a hash of server identity + surface + public handle. --binding-file overrides only that explicit path, never selects a sibling automatically. Limit record bytes to 4096 and directory records to 256; do not evict another live credential when full.
- updateBindingExpiry(path, expected, expiresAt) updates only the same validated server/surface/handle/proof record under the exclusive target lock, using the same fsync/atomic publish discipline. It cannot replace a proof or identity. This is consumed by heartbeat, not a generic credential overwrite/reset API.

<threat_model>
## Trust boundaries
Server issuance crosses an untrusted JSON parser into a local 0600 record; CLI/hook inputs select a record before a proof-bearing request. This protects protocol sessions, not mutually hostile processes under one OS account.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-71-04 | Information disclosure | CLI output, URL, pending journal | high | mitigate | Strict projections and header-only proof transport; private atomic files and sanitized error paths |
| T-71-05 | Spoofing / elevation | Record selection and hook identity | high | mitigate | Bind record to canonical server identity, surface and exact live handle; historical labels confer no private authority |
| T-71-06 | Tampering | Concurrent credential persistence | medium | mitigate | Exclusive target reservation, fsync, atomic publish, no sibling overwrite or lost-proof reset |
| T-71-SC | Tampering | Dependencies | high | mitigate | No packages added; use current CLI filesystem/crypto/runtime facilities |
</threat_model>
