## Implemented boundary and audit contract

- `Substrate` obtains the mandatory authority from `IndexStore.liveSessions({ leaseSeconds: config.liveSessionLeaseS })`. The deterministic test seam is `stores.steering.liveSessions`. Missing authority fails closed; no registry, old cache row, historical event, or optional cache flag grants access.
- `planning/steering-tools.ts` exports `LiveSessionBoundary`, `LiveSessionBoundaryError`, `LiveSessionRefusal`, `LiveSessionAuditFailure`, `LiveCallFailure`, `LiveSessionInvocation`, `LiveSessionAuditPort`, opaque `PreparedLiveCall` / `PreparedLiveDispatch`, and the shared input schemas. The common resource response is exactly `{ status: "refused", error: { code: "not-found" } }`; authority failure uses `session-unavailable`, required generic-audit failure uses `audit-unavailable`, and the target-independent principal refusal uses `principal-rate-limited` plus `retry_after_s`.
- The process-local principal bucket uses the existing `bucketStep`, `limitFor`, and `retryAfterSeconds` against authenticated surface/read-write class, independent of general admission mode or cache availability. Batch costs are reserved before any target resolution. A principal429 performs no authority lookup, directive inference, generic audit, or refusal audit. Internal rechecks do not spend another token.
- `Substrate.prepareLiveBatch(caller, calls)` validates/classifies live operations, reserves their costs together, then resolves target binding/operator policy. `auditPreparedBatch(batch, allCalls, transport)` is the sole injected-audit-port callsite and audits the complete original batch. It preserves the existing observability audit implementation's fail-closed-first ordering and whole-batch correction behavior. Canonical argument digests pin the batch and each one-use invocation; request IDs are not authorization keys, and duplicate invocations have separate entries.
- `executeLiveCall(invocation, effect, dispatch?)` consumes one matching opaque dispatch entry and performs the final SQL check before the effect. Direct-service/in-process MCP calls prepare once and use the same single-call batch-audit path. Invalid, consumed, mismatched, or altered dispatch/batch contexts cannot fall back to another charge or an unaudited mutation. Missing audit wiring refuses admitted required-audit mutations, not a fake successful audit. Read policy remains fail-open where no required mutation audit applies.
- Production `index.ts` supplies the fourth constructor argument, `LiveSessionAuditPort`, delegating to the existing `auditToolCalls(observability, caller.surface, calls, transport)`.
- HTTP MCP ordering is general `admitBatch` → live preparation → whole-batch boundary refusal, or one generic batch audit → request-local `createMcpServer(..., { preparedLiveDispatch })` → one-use wrappers. Boundary refusal dispatches no members: affected live calls get the common `isError` tool result; other request IDs get fixed `batch-not-dispatched`. Notifications receive no fabricated response. Non-live batches retain their existing generic-audit path.
- Refusal events contain only fixed operation/trusted caller metadata and `target_sha256`, computed over the bounded exact identifier with the `substrate.live-session-refusal.v1` domain and NUL separator. No requested target, proof, body, ownership reason, or audit-status decoration enters the public404. Generic audit context no longer copies live-target `session_id` to plaintext; canonical argument digest/key behavior remains intact.

## Actual lifecycle and private consumers migrated

### REST and MCP

- REST `POST /steering/sessions` issues after committed SQL; input is strict and cannot select an owner or public identity. Issued/updated receipts contain only public `session_id`, `repo_id`, `state`, `updated_at`, `expires_at`, and `event_stored`; issuance additionally returns the originating authenticated creator's one-time `session_binding`. Neither receipt returns private steering/planning hash. The proof remains the committed issuance receipt even if close races before delivery; the terminal identity cannot use that proof to read, renew, reopen or transfer ownership.
- REST `POST /steering/sessions/heartbeat` returns `status: renewed`, `session_id`, `expires_at` as the committed renewal receipt, not a continuing-liveness promise. REST close returns `status: closed`, `session_id`, committed `closed_at`, and `event_stored`. Best-effort lifecycle note publication failure sets `event_stored:false` without falsifying the SQL commit. Proof is header-only `X-Substrate-Session-Binding` for existing private targets.
- MCP `docs_steering_session`: omitted `session_id` issues; supplied `session_id` updates only an active issued owner-proof identity, never create-or-update. Repo and previous-state checks remain authoritative, and omitted private text/hash carry forward through the storage port. Added `steering_session_heartbeat` and `steering_session_close` with strict optional `session_binding`.
- Ordinary owner activity/heartbeat requires owner plus proof even for an operator. Explicit operator override applies only to private reads, close, queue, and acknowledgement, never unknown/expired/closed identity or lease renewal.
- `GET /steering/sessions` now calls `listLiveSessions` and the authority's SQL-filtered `listVisible`. Results are metadata-only for every caller, including operators, with `expires_at`, `truncated`, optional `next_cursor`; no private direction/hash/count fanout. `SessionsQuery` adds validated keyset `cursor`.
- `GET /steering/directives` calls `readLiveDirectives`, admits before inbox/history access, and rechecks after `durableAcknowledgedFor`. The durable helper is now private and takes an opaque prepared context rather than an unchecked string.
- `GET /steering/wait` calls `waitLiveDirectives`: one charged/audited request; per-session local close wake; SQL checks before holding and after every wake/release, including immediate ready directives and timeout. Wait slices are at most1000ms and clamped to the current lease hint and monotonic remaining request budget. No SQL transaction is held across the socket wait. Existing caps and once-only waiter/timer/listener cleanup remain.
- Queue/ack/list shared helpers use the same service execution wrapper, including direct-service calls. Operator allowlist, per-target rate, conflict confirmation, inbox audit-before-effect, and unkeyed REST queue/ack body shapes remain. Correctly bound non-operator writes are `operator-required`403; denied/nonexistent targets are404 first.
- **Mutation linearization correction:** after the inbox or SQL mutation commits, later close/outage does not convert its public queued/acknowledged/issued/updated/renewed/closed receipt into a no-effect404. Pre-effect binding/admission/audit and transactional checks remain. Closed-target private delivery still denies, even when an already-admitted queue commits a retained record. No distributed rollback or append-only audit rewrite was introduced.
- `parseAcknowledgeBody(body)` is pure and no longer accepts/reads an inbox or synthesizes an unknown-session sentinel. REST directive target inference happens only after principal admission. MCP retains required submitted `session_id`, which must match the inferred target.
- `acknowledgeSteeringWithState` is now exported from **`planning/steering-tools.ts`**, not delivery.ts. The low-level acknowledgement effect is module-private, so a merely prepared token is not an exported unaudited mutation API. All product callers and the new focused test use the new import; no compatibility re-export exists. The function's optional final arguments are prepared dispatch and transport.
- `planning/steering-delivery.ts` retains state mapping, notice/hint/sweeper behavior and types. `SessionTransitionContext` is trusted `LiveSessionAccess` plus `directiveId` and fixed `operation: "operator-ack"`. `LiveSessionStatePort({ authority, emit })` returns its committed SQL movement result, not a postcommit read denial. Close before state application leaves acknowledgement effective with state refused/no hint. Close after a committed movement retains truthful `session_state:applied`/unchanged metadata; failed final live authorization suppresses only `checkpoint_hint`.
- `SteeringReadUnavailableError` preserves the existing typed inbox/configuration503 response after successful target admission, separately from SQL authority failure.
