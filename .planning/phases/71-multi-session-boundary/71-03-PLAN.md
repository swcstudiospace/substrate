### Concrete preflight/audit/dispatch callback contract

Implement this contract in the existing service/steering-tools/observe/server/MCP modules, owned only by this integration executor:

- LiveSessionAuditPort.auditCalls(caller, calls, transport): Promise<AuditOutcome> is a trusted constructor dependency on Substrate. Production index.ts:66-71 injects a port that delegates to the existing observe.auditToolCalls with the already-created observability instance; preserve its policy sorting, fail-closed-first behavior, whole-batch denial and batchNotDispatched graph corrections. Direct-service tests inject a real recording/failing test port. Missing port returns sanitized audit-unavailable for admitted required-audit live mutations, never successful mutation or a no-op audit. No caller-supplied callback, boolean audited flag or body receipt can authorize an effect.
- Substrate.prepareLiveBatch(caller, calls) first validates/classifies applicable live invocations, reserves the mandatory surface/class costs for ALL of them before any target lookup/audit, then resolves all target bindings and operator policy. Calls with no live target (issue/discovery) still take admission. Mixed docs/brief are live only with explicit steering_session_id. Non-live tools remain unchanged. Tokens already spent before a later batch refusal stay spent, matching the existing admission model. A failed preparation returns the common boundary result before the generic audit sink is invoked;429 runs no audit at all. For a mixed MCP batch with a failed target preparation, dispatch NONE of its members: affected tool calls receive the exact common refusal as their isError tool result; other request IDs receive a fixed target-independent batch-not-dispatched response. Preserve valid JSON-RPC per-member IDs and notification rules; do not partially execute unrelated members or expose another member's target/reason.
- Substrate.auditPreparedBatch(preparedBatch, allCalls, transport) is the only operation that invokes the injected audit port after all preparations succeed. It audits ALL original batch calls once, including non-live members, using the unchanged canonical argument digest/structural-key pattern and public-safe generic context. Audit failure returns the existing auditRefusal whole-batch response and retains existing fail-closed-first/correction semantics; it does not replace a previously known target denial. On success it produces an opaque PreparedLiveDispatch containing one-use invocation entries bound to caller, operation/tool and canonical validated-argument digest. Multiple identical invocations each have their own charged entry; never key authorization solely by a client-supplied request ID. The entries exist only in this request and cannot be replayed in another call/batch. An audit receipt is not a continuing authorization grant: SQL rechecks still apply before effect/release.
- Substrate.executeLiveCall(invocation, effect, preparedDispatch?) consumes the matching one-use entry, rechecks authoritative state immediately before the admitted effect and at asynchronous release points, then executes the internal effect callback. Without a dispatch object (direct service call or in-process createMcpServer), it performs prepare plus the configured audit port itself. Invalid/consumed/mismatched supplied dispatch never falls back to skipping audit or charging again. Public transport/client schemas cannot provide the internal dispatch object. Low-level queue/ack shared consumers must enter this wrapper through SteeringWiring; no direct-service live mutation bypass is left merely because its route was audited elsewhere.
- HTTP MCP handleMcp ordering replaces server.ts:2658-2673 explicitly: keep existing general admitBatch first; invoke prepareLiveBatch next; return budget/boundary whole-batch refusal immediately if it fails; invoke auditPreparedBatch once next; preserve auditRefusal if audit fails; finally createMcpServer(substrate, caller, { preparedLiveDispatch }) and dispatch. The registered live wrappers claim the matching prepared invocation and do not re-charge or re-audit. An in-process MCP server lacking this HTTP dispatch context uses executeLiveCall's complete prepare/audit path. All non-live batch audit behavior remains unchanged.
- REST live routes replace their pre-handler auditedRest calls (notably server.ts:2159,2174) with executeLiveCall: pure parse -> principal admission -> directive inference/binding/operator denial -> required generic audit -> final authoritative check -> existing inbox/state mutation. Add corresponding lifecycle/private docs/brief/read integrations; do not call auditedRest a second time on an already-audited live invocation. Ordinary no-live-handle routes retain existing auditedRest semantics. This ordering applies to service entrypoints too, not just HTTP wrappers.
