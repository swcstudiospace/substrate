<interfaces>
Pin these new exports in existing planning/steering-sessions-store.ts, not a parallel authentication package. They are implementation contracts, not current exports:

- LiveSessionCaller = { surface: Surface | null; isOperator: boolean }; LiveSessionAccess = { caller: LiveSessionCaller; sessionId: string; sessionBinding?: string }. Caller is trusted injection, never decoded from a body.
- LiveSessionOperation = "private-read" | "owner-transition" | "heartbeat" | "close" | "operator-queue" | "operator-ack". Operation is selected by server code, never submitted by a client. Operators may bypass owner/proof only for private-read, close, operator-queue and operator-ack; they never bypass existence, lease or terminal status. Issuance always belongs to the authenticated surface; heartbeat and ordinary state transitions require that owner's proof even for an operator. Acknowledgement-driven transitions use operator-ack explicitly and do not renew the owner's lease.
- LiveSessionSnapshot contains session: SteeringSession, ownerSurface: Surface, issuedAt: string, expiresAt: string. It contains neither proof nor proof hash. LiveSessionMetadata is the allowlisted public projection session_id, surface, repo_id, state, updated_at, expires_at; no steering, planning_hash or directive counts.
- LiveSessionFailure = { ok: false; error: { code: "not-found" | "session-unavailable" } }; transition validation also returns a distinct typed invalid-transition result only after authorization. No target-specific reason or driver text is returned in a boundary failure.
- LiveSessionAuthority.issue({ caller, repoId, state, steering?, planningHash? }) returns a successful snapshot plus sessionBinding ONCE. It accepts no candidate ID, owner override or client time. read(access, operation), transition(access, { repoId, state, previousState?, steering?, planningHash? }, operation), heartbeat(access), close(access), and listVisible(caller, { repoId?, limit, cursor? }) all return async typed results. read/mutations always query SQL; listVisible applies owner/repo/active predicates before limit and returns metadata to non-operators. Bound limits/cursors; do not fetch another owner's rows and filter after the cap.
- listMetadata({ repoId, limit, cursor? }) is the seventh authority method and returns only LiveSessionMetadata for active/unexpired rows across surfaces. Its real consumer is the deliberately public-redacted sessionContext source in71-03; it does not accept or manufacture an operator caller, return private columns or renew leases. listVisible remains caller-filtered REST discovery. Keep these two policies explicit rather than fabricating operator identity to reuse a private listing.
- bunLiveSessionAuthority(sql, { leaseSeconds, randomBytes? }) builds the adapter; the randomness seam is test injection only. IndexStore.liveSessions({ leaseSeconds }) consumes it. Production time comes from PostgreSQL, evaluated after acquiring a mutation lock; no caller timestamp controls authorization.

Exact crypto format: session ID `ls_` + randomBytes(32).toString("hex"); proof independently generated randomBytes(32).toString("hex"). Proof hash is SHA-256 of UTF-8 `substrate.live-session-binding.v1`, NUL, exact session ID, NUL, proof. Refusal target hashing is a different domain, defined in 71-03. Compare fixed-length hashes with timingSafeEqual; never log either proof or proof hash. Use a fixed dummy hash for absent/malformed proofs where comparison is needed; do not claim globally constant-time database behavior.
</interfaces>

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-71-01 | Spoofing / elevation | Issuance and same-surface private access | high | mitigate | Independent CSPRNG proof, immutable globally unique owner, proof check per operation; no cache/ledger adoption |
| T-71-02 | Tampering / elevation | Lease, transition and tombstones | high | mitigate | Same-row transactional checks, SQL time after locks, permanent identity retention and no reopening |
| T-71-03 | Information disclosure | Authority snapshots / SQL failure | high | mitigate | Hash-only secret storage, allowlisted projections, sanitized typed unavailable, no driver/proof logs |
| T-71-SC | Tampering | Dependencies | high | mitigate | No package installation or new dependency; reuse node:crypto and Bun SQL |
</threat_model>
