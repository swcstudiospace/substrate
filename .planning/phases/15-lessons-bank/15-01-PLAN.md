# Plan 15-01: `substrate lessons` add, recall, digest, outcome; docs; proof

## Objective
Tier 1 of the lessons bank (SPE-5830): a lesson from a finished phase becomes one governed `fact` that a later phase recalls at discuss time and cites by entry id, with read-time success scores and milestone digests. The commands are CLI; the one server change is read-side (task 9, revised after review): `memory_search` gains `subject_prefix` and a keyset cursor so recall reads every lesson in scope. No table, kind or write-path change.

## Tasks
1. **Shared args** — new `packages/cli/src/args.ts` with `parseArgs`, `str`, `list` moved out of `index.ts` (which dispatches at import time, so a command module cannot import from it). `index.ts` imports them; no behavior change for existing commands.
2. **Lesson identity and bodies** — new `packages/cli/src/lessons.ts`: `identifier`, `slugify`, `lessonSubject` (`lesson:<milestone>/<phase>/<slug>`, at most 200 characters), `lessonKey` (`lesson:` + sha256(source, collapsed text)), `lessonBody` (`[lessonbank]` marker, `milestone/phase/outcome/tags/source` header, blank line, text), `digestBody` (`[lessonbankdigest]`, `lessons:` id list, excerpts dropped before ids), and readers `citableLesson`, `citableDigest`, `outcomeRecord` (headerless `lesson:` facts still read).
3. **SUMMARY extraction** — `parseSummary`: bullets under `## Lessons` with continuations, `[tags: …]`, `[outcome: …]`, bold-lead slugs, frontmatter `tags:` inherited; frontmatter `key-decisions:` for `--key-decisions`; `placeOf` (milestone/phase from the archive path), `milestoneFromState` (`.planning/STATE.md`).
4. **Gate replies and transport** — `interpret`: only `accepted && verified_persisted` with an entry id is `recorded`/`duplicate`; quarantined, denied, review, conflict, refused carry the gate's reason and remedy. `httpMemory`: `POST /memory` for writes; `memory_search` as a JSON-RPC `tools/call` POSTed to `/mcp` with the bearer token, plain-JSON or SSE replies, a reply without `result` thrown as a refusal; `page` for a paged `subject_prefix` call, throwing `LegacySearch` when the server rejects the arguments ("Invalid arguments for tool memory_search", JSON-RPC -32602) or answers a bare list; `Unreachable` for no answer; 10 s default timeout (`SUBSTRATE_TIMEOUT_MS` overrides).
5. **Scoring and ranking** — `scoreOf` = (1 + Σw)/(2 + n), newest report per citing phase; `rankLessons` = match × 0.5^(age/half-life) × (0.5 + score), zero-match dropped, digested ids excluded, newest digest per milestone ranked in their place; `renderPriorLessons` (`## Prior Lessons`, one line per entry led by its id).
6. **Commands** — `runLessons` dispatch for `add` (text or `--from`, `--dry-run`, `--skip`, one same-key resend on `unverified`, nothing retried otherwise, too-long refused before sending, run stops at the first unreachable write), `recall` (fails open: stderr, empty stdout, exit 0), `digest <milestone>` (`--ids`, `--unchecked`, `--text`), `outcome <id>` (existence check unless `--unchecked`, score before and after re-read from the server). Reads go through `BankReader`: every `lesson:`, `lesson-digest:` and `lesson-outcome:` entry paged with the cursor until `next` is null, at most 50 pages per family (stderr line if hit); on an older server, the marker searches with one stderr warning per command. Default scope `repo:` + `repoSlug()`. Wire `lessons` into `index.ts` and its help text.
7. **Tests** — new `packages/cli/src/lessons.test.ts` against a fake substrate over real HTTP (toy gate with the real reply shapes; `memory_search` over SSE, pages and a legacy mode): subject/slug/cap, header round trip, key stability, SUMMARY parsing and key-decisions, add-twice is one entry, quarantined and denied sent once and reported, unverified resent once under the same key and never cited, too-long never sent, dry-run sends nothing, `--skip`, scoring rules, ranking order, recall block cites ids best-first, digest lists ids and deletes nothing and recall cites it instead, outcome appends and moves the score without touching the lesson, typo id refused, recall fails open, a 401 is not an empty bank; 130 lessons under 150 newer facts all considered and the oldest recalled where the newest-100 window misses it, an outcome on it scored over 105 prior reports, a digest reaching back, the fallback against a server that rejects `subject_prefix` (one warning), the 50-page cap.
8. **Docs** — new `docs/lessons-bank.md` (commands, formats, wording rules and the hedge words, ranking, reading the bank and the fallback, digests, scores, the GSD discuss-time recipe and cite-by-id convention, Tier 2 exclusions); the `memory_search` contract in `docs/memory-governance.md`; README layout line and a paragraph under "Memory governance" linking it.
9. **Read-side paging (revised after review)** — `index-store.ts` `searchMemoryPage`: `subject_prefix` matched literally with `left()`, `before`/`before_id` keyset over `created desc, id desc`, `next` rendered to the microsecond when the page is full; `searchMemory` delegates to it, unchanged in reply. `service.ts` `parseMemorySearch` (prefix through `normalizeSubject`, `query` optional only with a prefix, `before` ISO-8601 with a zone, `before_id` only with `before`, `InvalidSearchError`) and `searchMemoryPage`. `mcp.ts`: the new optional arguments; a page `{ entries, next }` when any is given, else the bare list. Tests: live-PG `index-store.search.test.ts` (prefix with LIKE metacharacters, cursor over 257 entries with shared timestamps and sub-millisecond spacing at page sizes 100/33/7, no-parameter search identical to the old statement, superseded visibility) and `mcp.test.ts` (shapes, normalisation, refusals).

## Out of scope (deliberate)
