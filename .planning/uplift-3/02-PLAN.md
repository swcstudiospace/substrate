# N2 — Restart-durable SLO history, capacity runway and ledger-native notifications (plan)

**What.** (a) A versioned SLO checkpoint the server writes every minute and on shutdown and restores at boot, so `brief.p95`, the plane windows and the burn ledger survive a deploy and `/slo` can say how far back its numbers reach (`history: {epoch, since, checkpointAt}`); `/slo.breached` folds in plane and burn breaches. (b) A `capacity.index.runway_days` objective fitted over a bounded ring of `/healthz` size reads, carried in the same checkpoint. (c) A flag-gated notifier that turns a *sustained* breach / open breaker / recovery into exactly one ledger event (and one optional webhook POST), deduped through the checkpoint so a restart never repeats a transition.

**Where.**
- `packages/observability/src/checkpoint.ts` (new) — `SloCheckpoint` (`v: 1`, `epoch`, `writtenAt`, `since`, `metrics[]` counters/histograms with attributes, `planes`, `burn`, `capacity`, `notify`), `snapshotCheckpoint(instruments, planes, burn, epoch, extras)`, `serializeCheckpoint`, `restoreCheckpoint(json)` with hand-rolled narrowing (`config.ts` style; no schema library in this package), `CheckpointError`, the 4 MB refusal before parsing, every ring cut to its cap (newest kept). `checkpoint.test.ts`.
- `packages/observability/src/metrics.ts` — `Instrument.prior` layer + `merged()`; `Counter.seed` / `Histogram.seed` (replace, never add; bucket-count mismatch skipped); snapshots are `prior + live`; `MetricRegistry.seed(prior)` seeds only instruments the registry owns and only histograms whose bounds match, returning the names left out.
- `packages/observability/src/slo.ts` — `PlaneCountSample` exported; `PlaneWindow(windowMs, bucketMs, prior)` + `export()`; `runwayDays` threshold (14); the capacity section: `CapacitySample`, `CapacityRing` (≤ 1,440, 60 s dedupe, clock-backwards ignored), `evaluateCapacitySlos(ring, {volumeBytes, targetDays, minSpanMs})` with a mean-centred least-squares slope and a 24 h minimum span.
- `packages/observability/src/burn.ts` — `BURN_MAX_SAMPLES` exported; `BurnLedger(windowMs, minSpanMs, prior)` + `export()`.
- `packages/observability/src/config.ts` — `SUBSTRATE_SLO_RUNWAY_DAYS` into `slo`, `indexVolumeBytes` from `SUBSTRATE_INDEX_VOLUME_BYTES`. `index.ts` exports.
- `packages/mcp-server/src/config.ts` — `sloCheckpointPath` / `sloCheckpointRejected` / `sloCheckpointS` / `sloNotify {enabled, intervalS, sustainS, webhookUrl}`; `DEFAULT_SLO_CHECKPOINT_PATH`; `ConfigProbes.directoryExists` as a second `loadConfig` parameter (only `index.ts` supplies it, so no test harness discovers `/var/lib/substrate` on the machine it runs on); `sloConfigWarnings`.
- `packages/mcp-server/src/observe.ts` — synchronous restore at construction (registry started at the history's `since`, prior layers seeded, windows/ledger/ring/notify map restored, `epoch = prior + 1`); one boot warning for a corrupt/oversized/unreadable file; `evaluateBurn()` (ledger is now the observability's own, env passed through), `evaluateCapacity()`, `history()`, `checkpoint()` (`*.part` + rename, one in flight, write failures logged once per reason, > 4 MB refused), periodic timer in `start()` (`SUBSTRATE_SLO_CHECKPOINT_S`, 0 = shutdown only), `notifyRecords`; observer gains `capacity`.

- `docs/observability.md` (history, runway, notifications, routes and config tables), `docs/runbooks/substrate-red.md` (step 3 + the event table).

**Flags (defaults preserve today).** `SUBSTRATE_SLO_CHECKPOINT` (unset → default path only when `/var/lib/substrate` exists; bare runs and every test: disabled), `SUBSTRATE_SLO_CHECKPOINT_S` (60), `SUBSTRATE_INDEX_VOLUME_BYTES` (unset → runway `insufficient-data`), `SUBSTRATE_SLO_RUNWAY_DAYS` (14), `SUBSTRATE_SLO_NOTIFY` (off), `SUBSTRATE_SLO_NOTIFY_S` (60), `SUBSTRATE_SLO_NOTIFY_SUSTAIN_S` (300), `SUBSTRATE_SLO_WEBHOOK_URL` (unset). The only unconditional visible changes: `/slo` gains `capacity` and `history`, and `breached` lists plane and burn breaches too (per-array detail unchanged).

**Locks respected.** No new kind/surface (`warning`/`note` on `substrate`); no Greptime/Hindsight token outside `packages/mcp-server/src`; no new REST/MCP write (the notifier emits through `Substrate.emit`, so no `policy.ts` entry); no hostnames, no secret values, the webhook URL never printed; `new AuditLog(` / `new OtlpExporter(` still only in `observe.ts`; metric labels unchanged; the catalogue of four untouched.

**Tests (what each proves).**
- `checkpoint.test.ts`: round-trip of every section; after restore `brief.p95` and plane availability equal the pre-restart result with zero new samples; a new sample adds; a second seed does not double-count; the burn rate survives and the next spend is a delta; mismatched bounds / unknown metric skipped and reported; refusals (not JSON, version, epoch, times, bad points/attributes/notify, > 4 MB); rings cut to caps; an older writer without `capacity`/`notify` restores.
- `slo.test.ts` (capacity): 48 h at 100 MB/day vs 10 GB → `(10 GB − current)/100 MB`; < 24 h → insufficient-data; unset volume → insufficient-data naming the variable; floor and full-volume breaches; non-growing index ok/unbounded; one bulk ingest does not set the rate; ring dedupe/junk/clock/bound/restore.
- `slo-history.test.ts`: epoch 1 → 2 → 3 across real restarts on one path with series retained and `/metrics.startedAt = history.since`; corrupt and > 4 MB files → one warning, fresh start, next write repairs; no path → epoch 1 and the boot line; `loadConfig` probe semantics; the periodic writer fires atomically; unwritable path never throws; `breached` lists a plane and a burn breach beside `brief.p95`; `capacity` insufficient-data after one `/healthz`, fitted over a restored ring, breached against a small volume.
- `slo-notify.test.ts`: conditions per objective/breaker; event shape and 200-char summary; < sustain nothing, ≥ sustain exactly one warning then silence; a breach clearing before the sustain is forgotten; sustained recovery is one note and a later breach is announced again; never-announced objectives do not recover; restart with records → no duplicate, recovery still announced; plane/burn/capacity/breaker transitions each once, half-open stays open; webhook sent once, failure/timeout/throw never block or throw and never log the URL; a rejected emit is logged and not retried; `start()` schedules nothing without the flag; settings defaults and bounds.
