# N6 summary — Ledger coverage probe and verified archive before TTL

## What changed

1. **Coverage seam** — `packages/mcp-server/src/greptime.ts` `GreptimeClient.anchorCoverage({ now })`: four bounded reads (newest `anchors.period_start`; `anchorsBetween` over the 7-day `COVERAGE_LOOKBACK_MS`; one `to_unixtime(date_bin(INTERVAL '1 hour', "ingested_at"))` + `count` histogram over the same window of `event_ingest`, grouped — a count per hour, never the rows; the newest `ledger archive` note on `surface='substrate' AND kind='note'` bounded by `ts` over `ARCHIVE_NOTE_LOOKBACK_MS`). Answers `{ newestAnchoredHour, lagHours, uncoveredHours (≤ 48, newest kept, ascending), more, lastArchiveWindow }`. Eligibility: hour started ≥ `COVERAGE_ELIGIBLE_AGE_MS` (1 h) ago and `isClosed` under `INGEST_LAG_MS`. `lagHours` 1 is the steady state. `epochMsAnyUnit` normalises a timestamp cell in s/ms/µs/ns/ISO.
2. **Export seam** — `exportWindow({ from, to, after?, limit })`: `[from, to)` on `ts`, `("ts" > a OR ("ts" = a AND "id" > b)) ORDER BY "ts" ASC, "id" ASC LIMIT n` (no OFFSET), `next` = last row of a full page; first ingest record per event by id in `IN_BATCH` batches bounded below at `from − 1 h` (first-record rule); receipts via `anchorsBetween` on every page. `firstEventMs()` for the archive's first day. Every statement goes through `sql()` → `assertAppendOnly`; the store-lock test's SQL-sender set is unchanged (`greptime.ts`, `brief.ts`).
3. **Archive** — new `packages/mcp-server/src/ledger-archive.ts`: `archiveWindow` writes `events-<day>.ndjson` (the hashed shape via the now-exported `rowToEvent`), `ingest-<day>.ndjson`, `anchors-<day>.ndjson`, `manifest-<day>.json` `{ day, counts{events,ingest,ingestMissing,anchors}, first, last, chainTip, hourlyRoots (RFC 6962 per first-ingest hour over `(ingested_at, event_id)` order, `merkleRootHex`), sha256 per file, writtenAt, releaseSha? }`; `.part` + rename, data files before the manifest; a failure discards the parts. Refuses before writing: unclosed day, already-archived day, `/`, the working tree, `/opt/agent-substrate`, a checkout, a filesystem below `SUBSTRATE_DEPLOY_MIN_FREE_GB` read with an injectable `df -Pk` runner (`freeKbOf` reads the same field as `deploy-release.sh`; unreadable refuses). `verifyArchive(dir, day)` recomputes file digests, counts, every `eventHash`, per-session forks and the chain tip, hourly roots from the ingest file, and compares each hour with its receipt (`verified | partial | unanchored | mismatched`); findings are `{ kind: missing|manifest|sha256|count|parse|hash|chain|root|anchor, file?, event?, hour?, detail }`, never thrown. File shapes parse through zod at the boundary.
4. **Runner + CLI** — `packages/mcp-server/src/ledger-run.ts` (`coverage [--json]`, `archive [--until] [--out] [--page-size] [--json]`, `verify-archive <dir> [--day] [--json]`); `archive` plans `daysToArchive(firstEventDay..until)` skipping days with a manifest, `--until` defaults to the newest closed day, `--out` to `SUBSTRATE_LEDGER_ARCHIVE_DIR`, and emits one `note` per day (`session_id ledger-archive:<day>`, `summary "ledger archive <day>: …"`, `payload.action ledger.archive` with counts, cursors, chain tip, digests) through `Substrate.emit` — the record `coverage`/`/healthz` read back. Exit 0/1/2 as documented. `packages/cli/src/ledger.ts` + `index.ts`: `substrate ledger …` spawns the runner exactly like `index sweep` (no ledger import in the CLI package).
5. **Health** — `service.ts` `Substrate.ledgerJobs()`: 60 s memo (`LEDGER_JOBS_MEMO_MS`) of one `anchorCoverage` read; concurrent callers share the in-flight read; a caller waits ≤ `HEALTH_PROBE_MS` then answers `null` + reason while the read completes into the memo; failures memoised as `null` + redacted, host-scrubbed reason. `health().jobs = { ledger: { anchorLagHours, uncoveredHours, more, newestAnchoredHour, lastArchiveDay, computedAt } | null, ledgerReason }`; `/healthz` spreads it; status code untouched.
6. **Config** — `LedgerSettings.maxUncoveredHours` / `.archiveDir` via `boundedInt` and trim in `loadLedgerSettings`.
7. **Units** — `infra/vps/substrate-ledger-archive.service` (oneshot, `Slice=substrate.slice`, `MemoryMax=512M`, `ConditionPathExists` on the release's CLI entry, `ExecStart … ledger archive --out ${SUBSTRATE_LEDGER_ARCHIVE_DIR}`), `.timer` (`*-*-* 03:30:00 UTC`, `Persistent=true`), drop-in with the shared env file and the commented `Environment=SUBSTRATE_LEDGER_ARCHIVE_DIR=` line. Disabled by default; `infra/vps/README.md` "Daily ledger archive" is the operator's install order; `scripts/doctor-units.test.ts` pins the unit's shape.
8. **Docs** — `docs/greptime-ledger.md`: "Coverage and archive" (coverage rules, archive format, keyset read, gates, verify states, what it does not prove), *Retention* now states the precondition (verified archive of every expiring day) and the config table carries the two names.

## Flags and defaults
| Name | Default | Effect |
| --- | --- | --- |
| `SUBSTRATE_LEDGER_MAX_UNCOVERED_HOURS` | `2` | `substrate ledger coverage` exit 2 above it (or when the list was cut); `/healthz` reports regardless |
| `SUBSTRATE_LEDGER_ARCHIVE_DIR` | unset | `archive` needs `--out`; the unit refuses by name, writing nothing |
| `SUBSTRATE_DEPLOY_MIN_FREE_GB` | `5` | the archive's floor on `--out`'s filesystem; `0` disables |
| timer | disabled | operator enables after mounting the off-box path |

## How it is measured
`substrate ledger coverage` on the VPS (today: no anchor timer installed → `newestAnchoredHour` null or stale, 48 uncovered + `more`, exit 2 — the gap N1's doctor also reports); `/healthz.jobs.ledger` (`anchorLagHours`, `uncoveredHours`, `lastArchiveDay`); rehearsal twin: `ledger archive --until <yesterday> --out <scratch mount>` then `verify-archive` exit 0 → the first `lastArchiveDay`.

## Rollback
Unset both names and disable/remove the timer (`systemctl disable --now substrate-ledger-archive.timer`, `rm` the three files, `daemon-reload`). `jobs` is additive on `/healthz`; the coverage seams are reads. Archived files on the operator's mount are left alone. Or `git revert` the N6 range.
